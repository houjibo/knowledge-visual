## Context

当前四个主题位于同一学科树并使用四学段完成键；首页目录、搜索、进度、备份白名单和发布验证都以 `computer-ai` 为单一标识。见 [proposal.md](proposal.md) 中的拆分范围。

## Goals / Non-Goals

**Goals:**

- 让首页、学段导航、搜索和进度在产品行为及目录数据中统一使用两个独立学科标识。
- 保留现有主题书签和本地完成记录，使旧数据可继续计入进度并可备份。
- 在实际已交付内容上建立分学科入口，不显示没有主题支撑的空学段。

**Non-Goals:**

- 不增加新的教学主题或改写四个现有模型。
- 不为两个学科补齐尚未实现的全部年级课程。

## Decisions

- 以 `computer/` 和 `ai/` 作为新学科页面根目录。机器人算法和二进制像素归入计算机的小学、初中；分类器和神经元归入人工智能的高中、大学。按现有内容而非平均分配学段，避免展示空入口。
- 把样式和进度模块迁到根 `assets/` 的共享位置，保留兼容页面在 `computer-ai/`。旧入口提供双学科选择，旧主题地址使用静态重定向和普通链接兜底；发布包保留这些路由，搜索目录排除旧页面。
- 新进度键采用 `kv-computer-{stage}-progress` 和 `kv-ai-{stage}-progress`。读取时将对应旧 `kv-computer-ai-{stage}-progress` 合并到新记录，冲突时新值优先且不删除旧键；这样升级不会丢失完成状态，也允许用户自行备份旧数据。
- 首页进度统计通过新学科目录过滤主题；备份允许列表同时接收旧、新键，导出保留本机原始值，导入仍遵循已有的冲突保留策略。
- 更新静态清单、首页计数守卫、发布包和公网验收测试；以这些门禁而非手工目录维护主题数。

## Risks / Trade-offs

- [用户持有旧地址] → 保留旧入口、学段页和主题地址，静态重定向到对应新页面并保留可点击链接。
- [旧进度与新进度存在同名冲突] → 新键优先，合并旧键中其他有效主题，保留旧键，并测试两种记录同时存在的结果。
- [页面移动造成相对资源失效] → 为所有新页面运行静态引用校验、全页发布包加载检查和两学科代表路径交互测试。
- [某学科当前只覆盖部分学段] → 首页说明实际已有主题的学段范围，目录只发布存在的主题，不用空卡片表示计划课程。

## Migration Plan

先移动四个主题和共享资源，建立新入口与旧路由兼容；再切换首页目录、进度与备份键，并通过静态、浏览器、发布包和公网门禁。发布失败时回滚本次提交即可恢复旧单学科入口和旧键读取；新键不会删除旧记录。
