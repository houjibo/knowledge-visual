## Context

动机与可观察行为见 [proposal.md](proposal.md) 与 [spec.md](specs/middle-iot-autonomous-control-security-lab/spec.md)。相邻的 `iot-device-identity` 讲设备标识与隐私、`iot-internet-distinction` 讲概念区分，均不覆盖供应链、系统更新与自主可控。学习进度通过 `SubjectProgress` 按 `computer/middle` 命名空间保存。

CE25 第四学段“物联网实践与探索”内容要求（6）（印刷页 38）要求了解自主可控技术对物联网安全的意义，gap 指向供应链、系统更新、可控性，next_step 要求年龄适宜的设备维护案例与权威来源。

## Goals / Non-Goals

**Goals:**

- 让学习者从可操作的判断中理解自主可控：供应链可信、系统持续更新、核心技术与数据可自主掌控。
- 纠正“按品牌国籍判断自主可控”的简化认识，强调本地化、开放标准、数据自持、可替代等工程属性。
- 用固定案例呈现停止维护（EOL）、滞后补丁、断供/远程停服的安全风险。
- 保持模拟确定性，可直接以文件方式打开，无服务、无构建期依赖、无外部请求、不连真实设备。

**Non-Goals:**

- 不评价具体厂商或品牌、不涉及政治立场；案例为去品牌化的功能/渠道描述。
- 不连接真实设备或平台、不做真实漏洞扫描、不接收自由文本。
- 不宣称已完整覆盖该内容要求、整册教材或真实课堂成效。

## Decisions

1. **三步围绕“来源—维护—可控”。** 第一步供应链可信（官方渠道/可核验签名 vs 不明来源/被篡改固件）；第二步系统更新维护（及时补丁、停止维护 EOL、忽略更新）；第三步自主可控对照（数据自持、开放标准、可替代、本地化 vs 单一外部依赖、远程可停服）。
2. **自主可控用工程属性而非品牌判断。** 正确选项锚定“能否自主掌控技术、数据和服务连续性”，把“某国产品牌就一定安全/进口就一定不可控”作为干扰项，避免刻板结论。
3. **维护案例年龄适宜。** 用校园网关、智能电表等已在前序实验室出现的虚构设备，描述补丁、EOL、断供后果，不引入超出初中认知的复杂攻防细节。
4. **门槛与本地边界。** 三步全部正确才能进入下一步并保存进度；全程只在本机模拟，明确网络请求数为 0。受本地脚本约束，交叉表只能推进到 `partial`。
5. **归属初中计算机且只计一次官方分母。** 页面放在 `computer/middle/`，唯一映射到 CE25 物联网模块内容要求（6）；不在其他导航另造国家课程分母。
6. **复用本地进度契约。** 仅三步全对后在 `computer/middle` 进度命名空间记录完成；读写失败不阻断学习并支持重试。

## Risks / Trade-offs

- [自主可控话题可能被简化为品牌标签] → 用工程属性与可核验来源组织判断，明确自主可控是程度问题而非国籍二分。
- [虚构供应链案例可能被当成真实事件] → 全部标注虚构、去品牌化，真实采购与安全决策需结合权威标准。
- [本地演示无法满足“意义”的完整体验措辞] → CE25 该条仅从 `missing` 调整为 `partial`，真实供应链调研、安全运维实践与学习者迁移列为剩余工作。

## Migration Plan

不删除任何既有 URL 或进度结构。新增页面与模型，经现有清单/目录生成注册，更新唯一的 CE25 交叉表条目与证据记录，运行单元/浏览器/静态检查，推送功能提交，核验 Pages 与公开资源后归档。回滚方式为回退该功能提交；不迁移任何外部状态或用户数据。
