## Context

见 [proposal.md](proposal.md)。当前页面用四个 `.tab` `div` 监听点击，模式内容复用一个动态更新的 `#panel`；页签自身无焦点、角色或状态，切换时只改 CSS 类和模式变量。

## Goals / Non-Goals

**Goals:**
- 将现有四个模式入口变成符合 ARIA 页签模式的原生按钮，支持单停靠点、方向键循环和 Home/End 自动激活。
- 在同一动态面板上维护活动页签与面板的名称关联，保留现有模式渲染和点击行为。
- 自动化验证四种面板内容及桌面和窄屏交互。

**Non-Goals:**
- 不改实验知识内容、教学模型、进度里程碑、画布动画或课程导航。
- 不重构同一页面内的实验步骤和测验控件。

## Decisions

- **使用原生 `button` 并添加 `tab` 角色。** 原生按钮保留 Enter、Space、点击和触屏激活；相较于继续使用 `div` 手工模拟按钮，可减少键盘行为分叉。四个按钮置于命名的 `tablist` 中，使用 `aria-selected` 与 roving `tabindex` 暴露单一活动项。
- **复用一个 `tabpanel` 并动态关联活动页签。** 页面现有 `#panel` 会按模式重建内容；改为四个并存隐藏面板会扩大页面渲染改动。所有页签控制该面板，切换时更新 `aria-labelledby`，并保留面板可从页签组后通过 Tab 到达。
- **方向键采用自动激活。** 当前模式切换只更新本地 DOM 并重启本地画布循环，没有网络请求或明显加载过程，焦点移动时可立即显示内容。横向布局只处理 Left/Right，避免拦截正常页面滚动；操作遵循 [WAI-ARIA APG 页签模式](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) 的停靠点、方向键和面板焦点建议。
- **增加可见焦点样式。** 焦点轮廓与选中背景分开呈现，避免键盘用户仅凭颜色变化判断焦点。

## Risks / Trade-offs

- **动态内容可能造成面板标注与显示状态不同步** → 通过统一激活函数更新类、ARIA 状态、roving `tabindex`、面板标签和模式内容，并在每种输入路径断言同步。
- **按钮默认样式改变原有胶囊布局** → 显式继承字体和文字颜色，并在桌面与 320px 视口检查布局。

## Migration Plan

1. 为现有入口补充原生按钮、页签组语义和动态面板关联，保持现有 `data-mode` 与模式渲染接口。
2. 运行新增桌面/移动浏览器测试及静态、OpenSpec、完整站点检查；如回归失败先修复再继续。
3. 更新交互覆盖和风险线索，完成后提交、推送并核对 Actions 与公开页面。
