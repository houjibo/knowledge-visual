## Context

`generateCalc()` 在经典内联脚本中被页面初始化和答题计时器直接调用。题目答案始终为 0 到 10 的整数，当前页面已有本地 `shuffle()` 工具，可对有限数组做 Fisher–Yates 洗牌。

## Goals / Non-Goals

**Goals:**

- 选项只从完整的 0 到 10 有限整数域中生成，且正确答案唯一。
- 复用已有洗牌函数，保持各整数干扰项随机分布，不引入依赖。
- 用真实页面回归覆盖首次加载、三种运算、作答后续题和窄屏布局。

**Non-Goals:**

- 不改题目模板、答案计算、反馈时序、正确计数或其他学习模式。
- 不提取新的共享练习框架，也不扩展全站随机数 API。

## Decisions

1. **先枚举再抽取，而非持续重抽。** 从 0 到 10 的整数域中排除当前答案，再通过已有 `shuffle()` 取三个干扰项，最后洗牌四项。任意合法答案都恰有十个可选干扰项；数组规模固定，执行次数有上限。继续重抽即使增加尝试次数，也无法保证固定随机源结束。
2. **在浏览器层验证题意和交互。** 在固定随机源下读取页面呈现的算式并独立计算答案，校验选项范围、互异性、答题计分和下一题；覆盖加、减、乘及 320px 视口。这样可以同时捕获初始化阻塞与可见行为回归。

## Risks / Trade-offs

- **题目答案附近的干扰项分布可能不同 →** 从完整的 0 到 10 域均匀抽取，与原有 `randomInt(0, 10)` 的候选范围一致。
- **未来扩大答案范围却忘记同步选项域 →** 将选项边界验证加入回归，题目范围调整时会明确失败。

## Migration Plan

无需数据迁移。合并后通过 GitHub Actions 发布静态站点；若发布后回归失败，回滚该提交并保持原有题目数据不变。
