## Context

动机与可观察行为见 [proposal.md](proposal.md) 与 [spec.md](specs/middle-iot-device-identity-privacy-lab/spec.md)。相邻的 `identity-encryption` 讲人的账号凭据、`iot-internet-distinction` 讲物联网概念，均不覆盖“设备自身的数字身份”和“设备数据的隐私推断”。学习进度通过 `SubjectProgress` 按 `computer/middle` 命名空间保存，公开主题元数据由页面清单与主题目录生成。

CE25 第四学段“物联网实践与探索”内容要求（5）（印刷页 38）要求认识物联设备与数字身份的关系并保护隐私，交叉表 next_step 指明做“匿名设备标识与可推断信息的有限案例”。

## Goals / Non-Goals

**Goals:**

- 让学习者区分“设备的数字身份标识”与人的身份证号/账号，理解每台联网设备都有可被系统识别的标识。
- 理解即使不含姓名，长期设备数据也能推断作息、位置、健康等个人信息。
- 掌握匿名化标识与数据最小化两类可操作的隐私保护做法。
- 保持模拟确定性，可直接以文件方式打开，无服务、无构建期依赖、无外部请求、不连真实设备。

**Non-Goals:**

- 不连接真实设备或平台、不抓真实网络流量、不接收自由文本。
- 不涉及具体厂商或品牌；设备与标识均为去品牌化虚构案例。
- 不宣称已完整覆盖该内容要求、整册教材或真实课堂成效。

## Decisions

1. **四个虚构设备对应四类标识。** 智能电表（设备 ID）、智能音箱（序列号 SN）、智能手环（MAC 地址）、家用网关（与云账号绑定标识）；另设“人的身份证号”干扰项，强调设备身份不是人的法定身份但同样可关联到个人。
2. **三组设备数据流呈现“去标识≠匿名”。** 智能电表读数可推断在家时间，定位记录可推断住址与通勤，可穿戴心率/睡眠可推断健康状况；学习者要选出每类数据可推断的信息，建立“无姓名也可能识别个人”的认识。
3. **保护决策落到两种可操作做法。** 匿名化（用随机化、定期轮换的标识代替固定设备 ID/MAC）与数据最小化（只采集完成任务必需的字段、缩短保留期）；把“上报精确位置+长期保留”“直接拔电禁用所有功能”作为反例，前者过度采集、后者不是合理保护。
4. **门槛与本地边界。** 三步全部正确才能进入下一步并保存进度；全程只在本机模拟，明确网络请求数为 0、不连真实设备。受本地脚本约束，交叉表只能推进到 `partial`。
5. **归属初中计算机且只计一次官方分母。** 页面放在 `computer/middle/`，唯一映射到 CE25 物联网模块内容要求（5）；不在 AI 等其他导航另造国家课程分母。卡片、清单、搜索目录与发布校验经现有生成器/检查注册。
6. **复用本地进度契约。** 仅三步全对后在 `computer/middle` 进度命名空间记录完成；读写失败不阻断学习并支持重试，标识与选择不写入存储。

## Risks / Trade-offs

- [虚构标识可能被当成真实设备行为] → 明确为去品牌化教学案例，真实设备的标识与隐私政策各有差异，需以具体设备与法规为准。
- [匿名化可能被误解为绝对不可识别] → 说明匿名化降低关联风险，但与其他数据结合仍可能重新识别，数据最小化同样重要。
- [本地演示无法满足“保护隐私”的完整体验措辞] → CE25 该条仅从 `missing` 调整为 `partial`，真实设备观察、平台隐私设置与学习者迁移列为剩余工作。

## Migration Plan

不删除任何既有 URL 或进度结构。新增页面与模型，经现有清单/目录生成注册，更新唯一的 CE25 交叉表条目与证据记录，运行单元/浏览器/静态检查，推送功能提交，核验 Pages 与公开资源后归档。回滚方式为回退该功能提交；不迁移任何外部状态或用户数据。
