## Context

见 `proposal.md`。站点为无构建运行时依赖的静态 HTML，首页主题目录由页面盘点和导航链接生成；发布包通过白名单从 Git 跟踪文件构建，并部署在 GitHub Pages 子路径。当前学科进度按学科和学段 localStorage 键累计。

## Goals / Non-Goals

**Goals:**
- 复用现有静态目录、生成目录、发布包和进度统计契约，让新学科从源文件到公网链路可追踪。
- 使抽象计算概念能通过明确输入、可见状态、解释文本和重置操作学习。
- 让首批课程离线于服务端、无用户账户、无外部 AI 请求，并适配窄屏和键盘。

**Non-Goals:**
- 不将本切片扩展为编程 IDE、在线代码执行、真实生成式 AI、账号同步或教师管理系统。
- 不宣称四个体验课已穷尽任何国家课程标准；后续主题按课程图和差距台账迭代。
- 不移动或批量重构既有学科页面。

## Decisions

1. **采用稳定、可预测的分层路由。** 新建 `computer-ai/index.html`、`computer-ai/{primary,middle,high,uni}/index.html`，主题页分别使用 `robot-algorithms.html`、`binary-pixels.html`、`classifier-lab.html`、`neuron-forward-pass.html`。该布局与物理、化学学段目录和站内可生成目录兼容；不新增单页应用路由器，以保留深层链接及静态服务器能力。
2. **用 DOM/SVG 与原生控件实现可视化。** 网格、位图、散点和神经元结构使用语义 HTML/SVG；滑块、开关、运行、计算和重置用原生控件。相比 canvas 或框架，DOM/SVG 更容易键盘操作、窄屏重排、验证真实数值和在无运行时依赖下维护。
3. **进度沿用已知主题目录并按学段隔离。** 记录键为 `kv-computer-ai-{stage}-progress`，条目以稳定主题 slug 为键；只有触发主题明确的完成操作才写入。首页通过目录校验 slug 与总数，损坏或拒绝存储时显示不可用且保留课程交互。
4. **让首批主题表现逐级加深而非重复 AI 宣传。** 小学用指令序列理解算法；初中连接二进制与像素数据；高中用合成样本观察分类边界和误差；大学用输入、权重、偏置和激活函数复核神经元计算。每个模型配有概念解释、重置、状态反馈和可复现的自动化断言。
5. **把新页面接入全部生成与发布环节。** 页面盘点识别 `computer-ai` 和 `primary`；目录生成从其导航收集别名；首页总数由目录生成；静态发布白名单纳入新目录；发布后版本测试从首页搜索进入一项新交互。以上比仅加入首页卡片更能及时发现遗漏。
6. **课程设计参考权威框架但保留本地核验。** 课程图将数据、算法、网络、信息安全、AI 技术与人本伦理作为长期主线，参考教育部信息科技课程标准、教育部 AI 教育相关部署、UNESCO 学生 AI 能力框架和 CSTA PK-12 标准；本次单个主题仍须按页面具体目标核对，不能以引用框架替代教学审校。

## Risks / Trade-offs

- **[同一主题被误读为标准课程全覆盖]** → 学科页明确标注首批体验主题和持续补充状态；设计文档列出后续地图及未实现项。
- **[本地存储被阻止导致完成状态丢失]** → 交互与完成反馈独立运行；明确提示未保存，不请求账号或上传记录。
- **[GitHub Pages 子路径下资源路径错误]** → 所有页面使用相对路径；发布包构建和子路径浏览器回归验证新入口及主题资源。
- **[模型过度简化造成错误泛化]** → 分类器只使用虚构二维演示点，说明准确率只描述本练习样本；大学神经元显示完整公式与激活函数，不声称等同于完整 AI 模型。
- **[进度总数、站点目录或证据清单遗漏新页]** → 将学科根目录、阶段路由、总数、目录、release 和逐页清单纳入静态单测与 CI。

## Migration Plan

不需要迁移既有数据或改变现有 URL。先建立新路由和课程页面，再接入首页发现、进度和受控发布包；在本地运行静态、浏览器桌面/窄屏及发布包子路径验证后提交推送。GitHub Actions 成功且公网版本清单匹配提交后更新任务证据并归档变更。若部署或核验失败，保留修复提交并再次运行工作流；需要回退时恢复新目录、首页入口与白名单改动，不删除其他学科数据。
