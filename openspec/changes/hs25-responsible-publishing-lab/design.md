## Context

动机与可观察行为见 [proposal.md](proposal.md) 与 [spec.md](specs/high-responsible-publishing-lab/spec.md)。现有高中信息系统、对话交互与生成式 AI 负责任使用页面都使用独立、固定的本地模型；学习进度统一通过 `SubjectProgress` 按 `computer/high` 命名空间保存，公开主题元数据由页面清单与主题目录生成。

HS25 必修 2 内容要求 2.7（印刷页 15）要求按需求合理选用信息系统，并负责地发布、使用和传播信息，关联 HS20 的 2.6。初中 `webpage-publishing` 只做单页草稿与本页模拟发布快照，不涉及平台/权限/受众比较与发布后传播；中图人教版必修 2《信息系统与社会》设有“信息安全与社会责任”章节可作背景，但出版方目录未标出与 2.7 完全对应的小节，教材目录只是章次定位而非覆盖证明。

## Goals / Non-Goals

**Goals:**

- 用一个连贯的虚构校园成果发布任务，把“选用平台 → 发布前核查 → 撤回与传播后果”串成可操作的三步实践。
- 提供确定性的平台候选和一份带多处问题的待发布稿，让合理选用与发布拦截有可预测的正确判断和可检验反例。
- 保持模拟确定性，可直接以文件方式打开，无服务、无构建期依赖、无外部请求、无真实发布。

**Non-Goals:**

- 不接入真实平台、不调用网络服务、不接收自由文本、不做真实发布或转发。
- 不收集真实姓名等个人信息（稿件中的姓名为虚构示例），不演示绕过平台或删除他人副本的技术。
- 不宣称已完整覆盖 HS25 2.7、整本人教版教材或任何真实课堂成效。

## Decisions

1. **一个虚构校园节水成果发布任务，三个实践环节。** 任务要求向全校师生展示含同学反馈的节水成果，因此受众可控、可撤回的校内学习平台是合理选择；个人公开发布平台过度公开且传播不可控，班级协作空间受众过窄。单一场景把选用、核查、传播连成一条学习链；泛化的发布演示被否决，因为无法体现受众、权限与撤回边界的关系。
2. **固定平台候选替代真实平台操作。** 三个候选各自标注受众、权限范围和可撤回性，全部为合成数据，避免注册账号或连接真实服务，也让“按需求选用”可测试、可复现。
3. **发布前四项检查含三处固定问题。** 待发布稿在来源（结论无引用）、隐私（含虚构真实姓名）、授权（配图未确认授权）三项不通过，权限项在正确选用校内平台时通过。学习者须逐项判断并识别三个拦截项，问题稿不得进入发布；这满足项目本地数据约束，因此交叉表只能推进到 `partial`。
4. **撤回环节呈现传播不可逆。** 模拟发布后存在一个已转发副本：撤回原件可移除原帖，但平台不能保证删除他人已转发副本。正确判断区分“可撤回原件”与“已传播内容不可完全召回”，并明确本机快照不产生真实发布、网络请求数为 0。
5. **归属高中计算机且只计一次官方分母。** 新页面放在 `computer/high/`，唯一映射到 HS25 信息科技 2.7；可讨论信息社会责任，但不在人工智能等其他导航另造国家必修分母。卡片、页面清单、搜索目录与发布校验都经仓库现有生成器/检查注册。
6. **复用本地进度契约。** 仅在三步判断都正确后才在 `computer/high` 进度命名空间记录完成；读写失败不得阻断重试或泄露内容，稿件与平台数据不写入存储。

## Risks / Trade-offs

- [固定脚本可能被误认为真实平台行为] → 在页面与模型边界中明确标注为本地教学演示，不宣称真实平台功能或时效。
- [撤回反例可能被外推为平台通用规则] → 说明这是本例的固定情境，真实平台的撤回与转发机制各有差异，需以具体平台规则为准。
- [本地演示无法满足“发布与传播”的完整体验措辞] → HS25 2.7 仅从 `missing` 调整为 `partial`，把受控真实平台实践与学习者迁移列为剩余工作。
- [平台优劣可能被当成绝对结论] → 说明选用基于本例任务的受众、权限与撤回需求，不同任务的合理选择不同。

## Migration Plan

不删除任何既有 URL 或进度结构。新增页面与模型，经现有清单/目录生成注册，更新唯一的 HS25 交叉表条目与证据记录，运行单元/浏览器/静态检查，推送功能提交，核验 Pages 与公开资源后归档本变更。回滚方式为回退该功能提交；不迁移任何外部状态或用户数据。
