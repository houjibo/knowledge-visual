## Context

See [proposal.md](proposal.md) for the need. 现有主题是静态 HTML，目录和进度由仓库脚本及 `SubjectProgress` 维护；初中网络路径实验讲路径选择，尚未表达链路容量与并发共享。新主题继续采用纯前端、无账号和无网络上传的学习模型。

## Goals / Non-Goals

**Goals:**
- 让拓扑、配置、预测和模拟结果在同一可视工作台中联动。
- 用确定、可复核的公式描述连通性、共享链路和端到端瓶颈。
- 保留明确的设备角色与接入方式比较，并使学习进度可恢复。

**Non-Goals:**
- 不传输数据包，不探测本机或互联网，不测量 Wi-Fi 或实际吞吐率。
- 不实现真实路由协议、无线电干扰、拥塞控制、认证或网络安全配置。
- 不宣称仿真可以完成真实设备组网和课堂实测要求。

## Decisions

1. **用固定小型拓扑加可切换链路组装。** 以服务端、路由器、交换机、接入点、台式机和笔记本组成受限拓扑；用原生复选框、选择框开关链路/设置教学速率，并用 SVG 呈现状态。相较拖放任意图节点，固定拓扑能清楚解释每个设备职责、支持键盘操作并使模型测试穷尽。
2. **用纯函数模型而非计时网络动画。** 每台终端生成一个等量文件流；每条共同经过的链路按活跃流数量平均分配容量，每条流的教学吞吐率取其路径上可分容量最小值，时间由文件位数除以吞吐率计算。相较引入队列、协议重传或无线随机性，该模型有明确边界、可手算且可重复。
3. **学习任务按先组网、后预测、再观察、再比较推进。** 默认关闭 WAN 链路让学习者修复端到端连通；验证预测后才开放基线 Wi-Fi 模拟，之后可切到有线进行对照。链路状态或速率变化使两组实验失效；单纯在两种接入条件间切换时保留分别测得的快照，供同一配置下对比。
4. **速率为标注过的教学数值。** 选择低整数 Mbps 档位作为模型参数，不映射任何真实 802.11 版本、运营商套餐或设备标称性能。页面说明测得吞吐可能受协议开销、距离、干扰和负载影响。
5. **沿用站点本机进度接口。** 完成组网、正确预测、两种接入模拟和比较判断后才调用 `SubjectProgress.markComplete`；读写失败保留可见错误与重试入口。

## Risks / Trade-offs

- [模型简化可能被误当成真实测速] → 每处速率控件、图表和结果附“教学模型”说明；报告限定平均共享、固定需求、无协议开销假设。
- [拓扑配置变化使先前答案过时] → 变化时清除预测与实验结果，保留拓扑核验状态但要求重新预测。
- [手机屏幕放不下全拓扑] → SVG 使用自适应 viewBox，控制和结果按单列堆叠，测试 320px 窄屏和键盘访问。
- [浏览器存储不可用] → 主题继续开放并能完成操作，说明本机进度未能保存，并提供修复后重试。

## Migration Plan

新增主题文件并登记到高中目录和主题目录；运行模型、浏览器、完整静态及全站回归；完成 HS25 证据和 OpenSpec 规格归档；推送后等待 Pages 部署并对公开发布版本执行核验。若回归或部署失败，修复后重推；如需回退则还原该主题提交并重新发布。
