## Context

教育部《义务教育信息科技课程标准（2022 年版）》第四学段“互联智能设计”涉及物联网感知、传输与控制。NIST SP 800-183 将感知、通信、计算及执行作为 IoT 网络的组成，W3C Web of Things Architecture 1.1 区分传感器和执行器。本变更只建立可检验的课堂模型，不宣称满足真实硬件实践。

## Decisions

1. 固定三个场景和一套透明规则：湿度指数 0–100；收到指数低于 40 的读数命令水泵开，达到或超过 40 命令关；消息丢失时本模型沿用上一命令；水泵开使下一轮指数增加 20，关则减少 5，结果截取到 0–100。所有数值只是人为设计的教学值。
2. 独立纯函数计算每轮结果，页面状态只记录场景、轮次、预测、已揭示环节和已完成场景。所有可见数值和反馈来自同一模型。干燥场景观察两轮，能看到第一轮的动作改变第二轮读数。
3. 学习者先选命令并输入下一轮数值；答错仍可观察，但本轮不计完成。按“传感器→网关→控制器→水泵/环境”四步点击，全部完成后才能推进下一轮。三场景本轮都正确完成后才写入本机进度；写入失败保留重试按钮。
4. 使用静态 HTML、原生表单与按钮，无计时或运行时网络依赖。桌面、320px、键盘、`file://` 与 GitHub Pages 子路径一致可用。

## Risks and checks

- 物理误解：在规则区、反馈和依据区明确虚构指数、固定变化及“丢失时保持旧命令”只是本模型约定；不把它说成真实土壤或安全控制。
- 只点击不思考：预测和观察都作为本轮完成条件；错误预测不能写入进度。
- 发布失配：验证目录、搜索、数量、发布包、存储失败和本地/公网版本。
