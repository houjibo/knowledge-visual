## Context

参见 proposal.md 的 Why。挑战乘数为 1–9，因此正确乘积和选项的既有数值范围为 1–81。

## Goals / Non-Goals

**Goals:**
- 从有限候选中抽取三个不同于正确答案的干扰项。
- 保持题目范围、计分、计时和答题反馈。

**Non-Goals:**
- 不改变乘法挑战的题型、难度或计时长度。
- 不增加运行时依赖。

## Decisions

- 使用 1–81 的完整整数候选池，移除当前正确乘积后，通过既有有限洗牌抽取三个干扰项，再将正确答案加入并洗牌。候选池始终至少有 80 项，因此固定值和重复值也会有限结束。
- 不继续串联“答案附近随机值”和再次随机回退。该方式可能重复碰到已存在答案，重复随机源下没有终止保证；完整有限池同时保持有效乘法积范围。
- 浏览器回归固定随机值为 0 与接近 1，分别覆盖最小和最大乘积，并在桌面、移动及 320px 视口核对选项与作答反馈。

## Risks / Trade-offs

- 干扰项将来自完整乘积范围，可能不如仅用邻近答案具有挑战性 → 保持数值范围和答案唯一性，本次不扩大教学难度设计范围。

## Migration Plan

部署通过既有 GitHub Actions 全量检查和发布后版本核验；若出现回归，回退该提交并修正候选逻辑后重新运行完整流水线。
