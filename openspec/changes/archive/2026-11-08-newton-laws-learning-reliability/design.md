## Context

见 [proposal.md](proposal.md) 的复现证据。页面四个标签按 `.section` 显隐，`resizeCanvas` 依赖画布当前的 `clientWidth/clientHeight`；初始化和缩放目前会绘制所有标签。测验索引按题库长度循环，完成计数则只统计正确答题次数。

## Goals / Non-Goals

**Goals:**

- 让活动标签中的五张画布在展示、切换和缩放后保持可见且包含当前状态。
- 让切到其他标签时仍在运行的动画不会永久压成零高度，返回后可继续绘制。
- 区分单次作答得分与掌握进度，掌握进度按不同题目计数，并显示三题门槛。
- 保持现有题库顺序、答题反馈及全站进度存储接口。

**Non-Goals:**

- 重构电梯、斜面或连接体的物理方程及示意比例。
- 重新设计整页视觉风格、动画时钟或其他页面的标签交互。

## Decisions

1. **按活动标签分发绘制。** 建立集中渲染分区的函数：第一标签绘制三张牛顿定律画布，连接体标签绘制两张画布；初始化只绘制首个活动分区，切换和缩放只绘制活动分区。现有 HTML 电梯视图无画布，不需要进入画布分发。备选方案是在每个绘制函数里处理隐藏状态；该做法分散生命周期逻辑，且新增画布时更易遗漏。
2. **保存可恢复的画布逻辑高度。** `resizeCanvas` 首次绘制时读取画布原始 `height` 属性并保存为 CSS 固定高度；后续内部缓冲区按可见宽度、设备像素比和该逻辑高度设置。这样活动区动画即使在隐藏标签逐帧把内部宽度设为零，也不会丢失 CSS 高度，返回时可恢复宽度并继续绘制。备选方案是暂停每个标签的所有动画；这会扩大动画生命周期改造范围，本次先保留现有时钟行为。
3. **保存当前模拟状态而不是重置。** 分区切换只重绘现有状态对象；视口变化只重新测量活动分区尺寸。动画物理模型不变。隐藏期间继续运行的动画在返回时按最新状态绘制；暂停隐藏动画作为后续性能工作。
4. **用题库项索引去重掌握进度。** 会话内集合记录答对过的题目索引，重复题仍可增加本次作答得分，但不增加不同题目数。使用与作答得分分开的“不同题目 / 3”反馈，避免重复答题后得分变化被误认为知识地图已达标。已有 `PageProgress` 仍负责持久化最终完成状态。
5. **验收画布实际像素和学习进度条件。** 浏览器回归逐张检查画布显示尺寸、内部尺寸和非透明像素；还需播放动画、切走、等待隐藏帧后返回，确认逻辑高度、动画数值和绘制都保留。测验回归循环三次答对同一题并确认未达标，再答对两道不同题、刷新并确认完成状态持久化。桌面与窄屏项目都运行这些场景。

## Risks / Trade-offs

- [标签数量或画布归属变化后分发遗漏] → 回归测试明确列出两个含画布分区的五张画布，新增画布时必须同步扩展测试。
- [题库日后动态变题导致索引身份改变] → 当前题库固定且作为静态数组维护；若改为动态题库，应采用稳定题目 ID 并相应迁移去重策略。
- [隐藏分区的现有动画仍持续运行] → 不在本次改变动画时钟，切回活动分区时统一重绘；如性能测试发现后台负担，再单独为页面可见性增加暂停策略。

## Migration Plan

无数据结构迁移。先添加旧实现失败的浏览器回归，再实现活动标签绘制和题目索引去重；运行桌面/窄屏专项回归、静态校验与全页加载冒烟。若出现问题，回退该页渲染分发和进度计数变更即可，不影响已保存的主题完成记录。
