## Context

见 [proposal.md](proposal.md) 的问题证据。页面用五个顶层标签控制 `.section` 的 `display`，`getCanvasCtx` 按画布父容器的 `clientWidth/clientHeight` 设定绘制尺寸；隐藏分区测得的尺寸为零。当前初始化和 `resize` 监听器会绘制所有分区，`switchTab` 只更改活动 CSS 类。

## Goals / Non-Goals

**Goals:**

- 将画布渲染集中到当前活动分区，避免隐藏状态下的零尺寸绘制。
- 切换和缩放后用当前模型状态重绘，不重置学习者已调整的参数或动画数据。
- 回归测试检查可见画布的 CSS 尺寸、内部尺寸和像素内容。

**Non-Goals:**

- 调整化学公式、随机模型、动画速率、测验计分或进度持久化。
- 重构页面标签的键盘/屏幕阅读器语义；静态风险索引已标出这一独立差距。

## Decisions

1. **按分区选择渲染器。** 增加一个分区渲染函数，由标签索引分发到已有 `draw*` 函数。备选方案是在每个 `draw*` 函数内部判断可见性；这会把布局生命周期逻辑分散到各图表实现中，也容易遗漏。
2. **仅在显示后绘制。** 初始化先准备反应粒子，再绘制当前活动分区；`switchTab` 更新活动类后立即调用对应渲染器；`resize` 只重绘当前活动分区。切换前后保留既有模型状态。备选方案是推迟每个画布到 IntersectionObserver；页面仅五个静态分区且有明确切换入口，显式分发更简单、可测。
3. **以绘制结果而非仅 DOM 状态验收。** Playwright 对各可视化标签逐一切换并检查每张画布的可见宽高、内部宽高及至少一个非透明像素；再在桌面和窄屏视口运行。只断言画布可见无法发现透明的空画布，因此不作为唯一断言。

## Risks / Trade-offs

- [动画在隐藏期间仍可能逐帧执行并将其画布设为零尺寸] → 切回分区时渲染器会使用最新模型状态重绘；暂停隐藏动画属于另一项性能改造，不纳入此变更。
- [分区新增画布后渲染分发可能漏项] → 回归测试按分区显式列出所有现有画布，未来新增图表必须更新测试清单。
- [测试只验证浏览器画布输出，不验证每个模型的化学正确性] → 保留该边界，并在差距文档中继续列为后续内容核验项。

## Migration Plan

无需数据迁移或依赖升级。先加入可复现旧问题的浏览器回归，再实现活动分区渲染并运行桌面、窄屏测试及仓库静态检查；若出现回归，回滚页面渲染分发和关联测试即可，不影响已保存进度。
