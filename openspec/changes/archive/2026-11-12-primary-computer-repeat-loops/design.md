## Context

计算机课程目前只有小学顺序机器人与初中二进制表示。已制定的近期课程计划把循环作为下一知识点，并要求循环与展开执行逐步对应。沿用现有轻量 HTML、共享样式与本机进度方式，使内容能直接打开并部署在 GitHub Pages 子路径。

## Goals / Non-Goals

学习者能够构造有限重复、看到轮次及展开过程、预测完整程序的最终位置，并理解循环简化书写而不减少方向指令的执行次数。本轮使用两条方向指令、1–4 次重复及一张固定地图；嵌套循环、条件分支和自由代码执行留待独立增量。

## Decisions

- 地图为 5×5，左下角起点、第四列第二行目标。默认“向右、向上”重复两次，学习者调至三次后可完成；四次会在第六条经过目标后继续离开，用于区分“经过”与“程序结束”。墙位于第 1 列第 4 行和第 3 列第 5 行，防止把指令次序视为无关。
- 以选择参数生成最多八条有限指令列表，单步和定时运行共用同一执行函数；用执行序号计算轮次与轮内位置，避免独立状态漂移。
- 每次程序编辑停止计时器并从起点重新开始；暂停仅停计时器；运行中禁用重复启动与单步。页面离开时清理计时器。
- 将碰撞视为已执行但没有位移的方向指令，明确报告原因。成功须完整执行、最终抵达且无碰撞；初始和途中到达不保存进度。
- 使用 DOM 网格与文字状态，避免为简单地图引入画布库。两种程序表示共享当前执行标识，颜色之外还有序号、文字与 `aria-current`。
- 以 `SubjectProgress.markComplete` 返回值判断保存，失败保留成功结果并可重试；小学目录按卡片 slug 统计两个主题，首页根据目录累计计算机三个主题。

## Knowledge Evidence

[Microsoft MakeCode repeat](https://makecode.microbit.org/blocks/loops/repeat)将循环解释为按指定次数运行程序片段，并给出重复四次的例子；2026-11-12 已核验。本站的两条指令与展开长度由有限枚举和逐步位置测试检查，不以动画速度作为程序效率结论。此主题是确定次数循环的入门示例，不构成完整算法课程。

## Risks / Trade-offs

固定地图便于核查，但学习迁移仍需真实学习者反馈。最多八条指令避免无限执行；定时器暂停和编辑清理必须经过实际浏览器检查。已有共享存储策略保留损坏原文，因此存储不可用只提示未保存，不能自动覆盖修复。

## Validation

专项测试检查展开和每一步坐标/高亮、两次失败/三次成功/四次经过后失败、碰墙/边界、暂停恢复、运行中编辑、重置、减少动态效果、320px、历史进度与异常存储、首页发现与数量、直接文件及发布包子路径。通过完整 `npm run check` 后提交，核实对应 Actions 与公网 revision 后归档。
