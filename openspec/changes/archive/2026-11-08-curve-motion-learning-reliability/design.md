## Context

见 [proposal.md](proposal.md) 的本地复现和代码证据。页面包含四个标签、五张画布和八道循环测验题；`switchTab` 只切换可见类，初始化与缩放会绘制所有画布；隐藏画布的动画回调可能把内部尺寸重设为零。

## Goals / Non-Goals

**Goals:**

- 保持活动主题绘制路径集中且明确，画布重新显示时能够从现有状态恢复。
- 将每次答题得分与不同题目掌握进度分离，继续使用现有全站完成存储接口。

**Non-Goals:**

- 不暂停或改写各个动画时钟，不更改运动方程和教学文本。
- 不将未达标的题目索引集合持久化到跨刷新状态。

## Decisions

1. **按活动标签分发画布绘制。** 第一标签绘制小船，第二标签绘制平抛和斜抛，第三标签绘制水平圆周和竖直圆周；初始化、标签切换和窗口缩放都通过同一分发入口，仅重绘活动标签。其他方案是在每个绘制函数内分散隐藏状态处理；这会重复生命周期逻辑，并增加新增画布漏登记的可能。
2. **保留原始画布逻辑高度。** 首次绘制时从 `height` 属性保存逻辑高度并设为 CSS 高度，缓冲区高度按逻辑高度和设备像素比设置，宽度继续依据当前显示宽度测量。隐藏动画回调即使将画布宽度写成零，也不会丢失恢复所需的显示高度；重新进入标签时分发器会按当前状态重绘。暂停各个动画循环需要逐个改造状态生命周期，本次不扩大范围。
3. **用题目索引去重掌握进度。** 会话内集合记录答对过的题目索引，五题门槛与现有八题、60%正确率门槛一致；重复答对仍增加本次答题得分，但不同题目数只增加一次。新增独立的 0 / 5 显示；`PageProgress` 继续负责完成状态持久化，刷新后已完成的页面显示 5 / 5。
4. **针对可观察行为验收。** 桌面和窄屏浏览器回归检查五张画布的显示尺寸、缓冲区尺寸和非透明像素；运动参数变化后切走并返回、缩放后继续保持；练习循环重复答对同一题五次，再验证五道不同题完成及刷新恢复。

## Risks / Trade-offs

- [分区与画布归属表遗漏新增画布] → 测试逐一列出五张画布并覆盖三个含画布标签。
- [会话内去重集合在未完成时刷新会清空] → 当前契约只要求已完成状态刷新恢复；若后续需要保留未完成测验进度，再单独定义持久化格式和迁移行为。
- [隐藏期间动画继续运行并占用资源] → 本次仅保证重新显示后可恢复；如后续性能测量证实后台负担，再另行设计页面可见性暂停策略。

## Migration Plan

不迁移已有存储。先提交能在旧实现中复现尺寸为零及重复题提前完成的回归，再实现活动标签绘制和去重计数；运行桌面/窄屏专项测试、静态校验与全页冒烟，通过后归档并按主分支 Actions 部署。回退本页渲染分发和计数改动即可，不影响其他页面状态。
