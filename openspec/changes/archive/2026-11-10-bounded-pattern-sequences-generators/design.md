## Context

见 `proposal.md` 的问题说明。单个静态页面在初始化时同步创建图形、数字和涂色题；限时挑战另有图形和数字选项生成路径。所有路径共享本页的随机整数与数组打乱工具，页面保持无构建步骤、无运行时依赖。

## Goals / Non-Goals

**Goals:**
- 让题目选项和涂色空格的生成工作量由有限候选集大小决定。
- 保持题型、正确答案、反馈、计分和静态访问方式不变。
- 用浏览器回归覆盖初始化、模式切换、挑战开始、正确作答和窄屏布局。

**Non-Goals:**
- 不调整题目教学内容、规律类型、计时长度或视觉风格。
- 不修改其他页面的随机生成器或引入共享运行时模块。

## Decisions

1. **在本页使用有限候选池构造选项。** 先排除正确答案并去重，再打乱候选并取所需干扰项，最后打乱完整选项。图形候选来自现有图形集合；数字候选由当前近邻项与有限的正整数范围组成。相比重抽随机数，该方式在随机源返回同一值时仍然结束，并保留现有题型及干扰项风格。
2. **用网格坐标清单无放回选取空格。** 先列出所有有效坐标，再打乱并截取所需数量。相比逐次随机抽坐标并排重，此方式不会因重复坐标而循环。
3. **用浏览器端固定随机值验证实际交互。** 页面初始化测试分别固定 0 和接近 1；挑战专项在页面初始化后注入可控序列，以覆盖图形挑战和“答案较小、近邻候选重复”的数字挑战。回归还会根据可见规律独立核对正确选项、完成涂色并检查窄屏溢出。

## Risks / Trade-offs

- 有限候选池可能改变干扰项的抽样分布 → 保留近邻候选优先级，并检查答案唯一、题目可理解及桌面/窄屏布局。
- 固定随机值会产生可预测排列 → 这只用于确定性回归；生产环境仍用浏览器随机源，有限池仅保证终止与互异。

## Migration Plan

不需要数据迁移。提交后由现有 GitHub Actions 执行检查、构建和 Pages 部署；部署后核对公开资源版本。若发布核验失败，修复验证或部署问题后重新推送，不将未核验提交记为完成。
