## Context

当前挑战题在 5×5 网格上连续随机抽样，直到填满四个不重复选项。`generateOptions` 与 `generatePairOptions` 都没有尝试上限；若随机源重复命中已有坐标，出题事件会一直占用主线程。页面已有 Fisher–Yates `shuffle`，坐标全集只有 25 个位置。

## Goals / Non-Goals

**Goals:**

- 将两个方向题型的候选空间明确为有限的坐标全集。
- 保留四选一、选项随机顺序及现有学习进度和答题反馈行为。
- 用固定随机值覆盖最小和最大坐标，直接验证出题可完成。

**Non-Goals:**

- 不改变网格边长、题型比例、挑战时长、计分规则或主题完成门槛。
- 不重构其他小学数学页面的随机题生成器；其他静态候选需单独复现并立项。

## Decisions

1. **从有限坐标集合中抽取干扰项。** 枚举 1～5 行列组合，排除正确位置，打乱候选后取前三项，再与正确答案一起打乱。相较继续随机重试或仅增加尝试次数，这让终止步数由 25 个坐标直接限定，也保持干扰项分布覆盖整个网格。
2. **共享坐标到选项文字的生成路径。** 两种题型使用同一有限候选逻辑，只通过格式化函数生成“第几列第几行”或“(列, 行)”，避免两份代码的边界行为漂移。相较引入新依赖或全站共享模块，这个局部函数符合单页自包含结构。
3. **端到端固定随机回归。** 用恒定 `Math.random` 分别触发 (1,1) 与 (5,5) 两种题型；断言及时出现四个唯一选项、正确答案计分。相比静态检查 `while` 字符串，浏览器行为能复现并防止主线程被阻塞。

## Risks / Trade-offs

- [风险] 固定取候选顺序会使极端随机值下的干扰项集中在网格某一侧 → 每次先打乱整个有限候选集，再选取前三项。
- [风险] 页面未来修改网格边长却未更新枚举范围 → 任务和回归把当前 1～5 范围作为明确契约；若扩网格需同步调整候选域与边界用例。

## Migration Plan

无需数据迁移。验证挑战仍能出题并判分后归档 OpenSpec 变更；若回归失败，恢复原选项逻辑不会影响已保存进度或链接。
