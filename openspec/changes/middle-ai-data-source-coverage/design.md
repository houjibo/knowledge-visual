## Context

见 [proposal.md](proposal.md)。现有初中 AI 主题用四条样例说明标签冲突；人工智能主题统一在本地静态页面运行，通过 `SubjectProgress` 记录完成情况。课程图下一项是数据来源与代表性。

采样偏差与样本代表性取决于任务及目标场景。Google 的机器学习课程将未反映真实数据分布的样本选择归入 selection bias，并指出评估数据应覆盖预期场景；本实验仅将这些概念转成可观察的课堂问题，不声称有限的合成集合能估计真实分布或模型表现。[来源](https://developers.google.com/machine-learning/crash-course/fairness/types-of-bias)、[数据集划分](https://developers.google.com/machine-learning/crash-course/overfitting/dividing-datasets)。

## Goals / Non-Goals

**Goals:**

- 让学习者亲手选取样例，观察采样条件、类别数量和条件组合覆盖之间的差异。
- 在相同样本总量和相同类别数量的前提下提供窄来源与跨条件对照。
- 保持新增主题与现有目录搜索、进度、静态发布和公网核验一致。

**Non-Goals:**

- 不训练分类器，不输出预测准确率、群体公平结论或真实世界代表性分数。
- 不使用真实人员属性、外部图像、网络服务或学习者输入。
- 不扩展到隐私主题、生成式 AI 或跨学段数据课程。

## Decisions

### 用固定的有限目标集合隔离“来源覆盖”变量

页面展示 8 张虚构图案卡，按“明亮/低照度”与“圆形/三角形”形成四个组合，每个组合两张。默认选中明亮条件下的 4 张；对照预设仍选 4 张，且两类各两张，但每个条件组合选一张。这样两个样例集的数量和标签总数相同，主要差异是所覆盖的光照条件。

备选方案是展示随机抽样或真正生成随机样例。没有生成器会让例子更容易复查，也避免每次随机结果改变教学结论；数据量很小且固定，所以页面只讨论该集合内的覆盖。

### 支持预设与逐卡选择

提供默认窄来源、等量跨条件和恢复初始三个操作，并保留 8 个具名原生复选框供学习者自行组合。实时矩阵显示每个条件组合已选数与总数，缺失组合以文字和图形双重提示。

只提供两个固定按钮的方案虽更简单，却不允许学习者检验其他取舍。自由拖拽样例卡虽然直接，但触屏、键盘和读屏操作成本较高，因此不采用。

### 以条件组合计数作为进度门槛

只有四个条件组合都至少被选中一张样例时，主题记录为完成。此门槛表示学习者操作过完整覆盖集合，不等同于样本量足够、抽样无偏或模型表现可靠。存储写入失败只影响进度记录，不影响样本交互。

### 复用现有静态站点管线

页面放在 `ai/middle/data-source-coverage.html`，使用相对路径共享样式和 `SubjectProgress`；首页搜索目录、初中主题目录、学科主题总数和部署后资源检查同步增加条目。不增加依赖或新的进度存储键。

## Risks / Trade-offs

- [有限目标集合看起来像统计学上的代表性证明] → 所有计数标为“本演示集合”；说明覆盖四种预设组合不代表真实数据或模型结论。
- [用户把光照覆盖误当成准确率提升] → 页面始终不计算预测和准确率，只描述已观察/缺失的条件。
- [八个样例卡在手机屏幕上变窄] → 移动端使用单列布局，矩阵单元允许换行，并在 320 CSS 像素测试无横向溢出。
- [加入新主题使现有进度总数或目录漏项] → 用目录总数、搜索、进度、发布清单和严格 OpenSpec 检查验证同步。

## Migration Plan

新增 slug `data-source-coverage` 到现有 `kv-ai-middle-progress` 目录，不更换或清理任何存储键。更新目录以纳入新主题，旧浏览器记录继续保留。回滚时还原新增页面及目录记录即可；遗留的同名进度项将作为目录外项目忽略，不改变其他主题进度。
