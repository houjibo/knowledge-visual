## Context

见 [proposal.md](proposal.md)。应用题和挑战题都在页面脚本中即时生成；随机数工具使用 `Math.random()`，因此固定值可复现重抽无法前进的路径。

## Goals / Non-Goals

**Goals:**

- 让所有相关生成路径以有限候选完成，保留现有题目和反馈方式。
- 选项以数值去重，避免不同字符串表示同一个数。

**Non-Goals:**

- 不调整题型分布、教学文案、进度记录或挑战计分。
- 不修改其他主题页面或公共随机数工具。

## Decisions

- 选择第二个物品时，从场景物品数组中选一个非零偏移量并环绕索引，避免“抽到相同再重抽”。相比增加重试上限，这能直接保证不同且不依赖随机序列变化。
- 保留已有的易错项，再从答案附近按 0.1 递增构造固定长度的正负候选；按数值排除重复与不合法值，最多追加到四项后停止。相比无限随机偏移，这使完成步数有明确上界；相比完全替换干扰项，保留当前题目已有的教学意图。
- 应用题允许非负候选，挑战题沿用严格正数限制。最终继续使用现有有限洗牌函数。
- 回归通过页面初始化后调用当前题型生成入口，以首个随机值选择目标题型、后续固定为 0，覆盖原先发生重复补选的路径；同时检查加、减应用题答案与选项数值。

## Risks / Trade-offs

- [偏移候选与已有选项重合] → 采用 20 个正负步长候选并按数值过滤；回归检查四个选项和正确答案唯一性。
- [近邻干扰项过于接近] → 仅在已有候选不足四项时追加；沿用十分位间距，并保留现有候选优先级。

## Migration Plan

页面是静态资源，不需要数据迁移。通过本地浏览器回归和站点发布后验证；若部署验证失败，回滚页面和对应回归的提交。
