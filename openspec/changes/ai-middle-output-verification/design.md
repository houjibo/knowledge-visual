## Context

初中人工智能主题页均为自包含静态 HTML，并用 `assets/js/subject-progress.js` 记录本机进度。目录、首页 AI 总主题数、主题清单、交互证据和发布关键资源均有静态或自动化校验，新增页需要一并维护这些索引。

## Goals / Non-Goals

**Goals:**
- 让学习者能逐条对照固定回答与简短、可追溯的资料摘要。
- 让三种证据状态容易区分，尤其避免把资料缺失误读成反证。
- 沿用既有静态页、原生表单和本机进度模式，保持 320px 可用。

**Non-Goals:**
- 不调用生成式模型，不从外部抓取证据或上传学习者选择。
- 不评价通用 AI 系统，也不把 NASA 的有限资料包装成完整的生命探测结论。

## Decisions

- **每次提交核对四条独立陈述。** 使用四组原生单选框，统一“核对我的判断”后展示逐条说明。相比逐题立即揭晓答案，这能保留学习者先拆分和比较整段回答的练习；允许修改后重交。
- **类别与反馈依据直接写在静态页面中。** 三张 NASA 资料卡覆盖火星大小、卫星和行星平均日距。NASA 页面链接只在学习者主动打开时访问；页面学习和测试不依赖外网。
- **用“证据不足”标记未被当前卡片覆盖的现存生命陈述。** 说明仅针对题内资料范围，明确不能推出生命存在或不存在；不以宽泛的“真/假”标签代替证据关系。
- **完成需四条全部正确。** 错误或漏答不会保存进度；正确重交后调用既有 `ai/middle` 进度接口，存储失败不阻断核验。
- **更新所有人工维护入口。** AI 学段目录、首页计数、搜索输入来源所依赖的静态目录、浏览器测试命令、主题交互证据和发布资源校验必须与新页保持一致；自动生成的清单由对应脚本再生成。

## Risks / Trade-offs

- NASA 页面内容可能改版 → 在卡片中仅使用少量稳定事实，保留具体来源链接，并将“有限资料”边界写在页面；本地证据摘要不依赖远端内容加载。
- 学习者可能把题内分类误当作对真实 AI 输出的质量保证 → 页面显著说明回答是固定演示，练习展示的是核验方法，不是模型评估结论。
- “火星现存生命”涉及开放科学问题 → 正确反馈只限定为本组证据卡不足，禁止外推为生命存在/不存在结论。

## Migration Plan

新增页和浏览器专项测试后，更新目录、进度总数、搜索/发布清单与文档；运行专项测试和仓库静态检查，再运行全量 `npm run check`。通过后校验 OpenSpec 并归档变更，按项目发布流程提交和推送；若发布核验失败，先保留活跃变更并修复，不记录为已交付。
