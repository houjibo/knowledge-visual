## Context

动机与可观察行为见 [proposal.md](proposal.md) 与 [spec.md](specs/middle-iot-experiment-procedure-prep-lab/spec.md)。相邻的 `iot-sensor-feedback` 讲虚拟传感器阈值反馈，不覆盖实验规程、安全与数据记录流程。学习进度通过 `SubjectProgress` 按 `computer/middle` 命名空间（键 `kv-computer-middle-progress`）保存。

CE25 第四学段“物联网实践与探索”内容要求（3）（印刷页 38）要求遵守实验规程、搭建原型并收发/汇集/使用设备数据。next_step 明确虚拟模型仅作真实器材实验的先修，因此本页只覆盖可在固定案例内训练的规程与数据流程，不模拟“亲手搭建”。

## Goals / Non-Goals

**Goals:**

- 让学习者掌握物联网实验的安全规程：通电前检查、断电插拔、防静电、不私接电源、异常先断电。
- 能把一次温湿度采集实验的步骤排成正确顺序，理解每步目的。
- 梳理设备数据从采集、传输、平台汇集到分析使用、归档的完整流程。
- 保持模拟确定性，可直接以文件打开，无服务、无构建期依赖、无外部请求。

**Non-Goals:**

- 不替代真实器材实验：不要求、也不假装学习者已搭建物理原型或完成真实设备数据收发。
- 不连接真实设备或平台、不做真实数据采集、不接收自由文本。
- 不宣称已完整覆盖 IOT-03 的“搭建原型与真实收发”，仅作为先修证据推进到 `partial`。

## Decisions

1. **三步围绕“安全—步骤—数据”。** 第一步安全规程判断（正确/错误操作）；第二步实验步骤排序（六步）；第三步数据记录与汇集使用流程匹配。
2. **步骤排序用固定正确序列。** 明确目的→检查器材→按图连接→通电采集→如实记录→断电整理，学习者对打乱的卡片排序，模型校验相邻顺序。
3. **数据流程对应五个环节。** 设备采集→网络传输→平台汇集→分析使用→归档留存，与既有 `smart-society-system` 的系统要素呼应但聚焦实验数据流。
4. **全程显式标注先修边界。** 页面边界说明与完成反馈都提示“这是真实器材实验前的规程先修，动手搭建与真实收发仍需在实验室完成”，避免把虚拟训练误当实践达成。
5. **门槛与本地边界。** 三步全部正确才能进入下一步并保存进度；全程只在本机模拟，网络请求数为 0。交叉表只能推进到 `partial`。
6. **归属计算机学科初中且只计一次官方分母。** 页面放在 `computer/middle/`，唯一映射到 CE25 物联网模块内容要求（3）；不并入人工智能学科，也不在其他导航另造国家课程分母。
7. **复用本地进度契约。** 仅三步全对后在 `kv-computer-middle-progress` 记录完成；读写失败不阻断学习并支持重试。

## Risks / Trade-offs

- [虚拟先修可能被误读为完整实践] → 在页面、OpenSpec、核查记录与交叉表 gap 中四处明确未覆盖真实原型搭建与真实设备数据收发，`partial` 不升 `verified`。
- [固定实验场景代表性有限] → 用温湿度采集这一初中常见、年龄适宜的场景，真实实验的器材差异由教师与实验室规程补充。
- [本地演示无法满足“搭建原型”的措辞] → 这是该要求的固有边界，剩余部分应转入需真实器材的实践工作流，而非在仓库内硬凑。

## Migration Plan

不删除任何既有 URL 或进度结构。新增页面与模型，经现有清单/目录生成注册，更新唯一的 CE25 交叉表条目与证据记录，运行单元/浏览器/静态检查，推送功能提交，核验 Pages 与公开资源后归档。回滚方式为回退该功能提交；不迁移任何外部状态或用户数据。
