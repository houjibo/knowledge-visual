## Context

动机与可观察行为见 [proposal.md](proposal.md) 与 [spec.md](specs/high-device-platform-choice-lab/spec.md)。现有高中信息科技页面都使用独立、固定的本地模型；学习进度统一通过 `SubjectProgress` 按 `computer/high` 命名空间保存，公开主题元数据由页面清单与主题目录生成。

HS25 必修 1 内容要求 1.3（印刷页 12）要求为具体学习任务选择数字设备与平台，开展自主或合作学习并运用平台数据，关联 HS20 的 1.3。中图人教版必修 1《数据与计算》设有“认识数据与大数据”“数据处理与应用”等章节可作背景，但出版方目录未标出与 1.3 完全对应的小节，教材目录只是章次定位而非覆盖证明。

## Goals / Non-Goals

**Goals:**

- 用一个连贯的虚构野外考察任务，把“选设备 → 匹配平台 → 解读平台数据”串成可操作的三步实践，覆盖“自主/合作学习”和“运用平台数据”两个要点。
- 提供确定性的设备、平台候选和固定协作数据，让匹配决策有可预测的正确判断和可检验反例。
- 保持模拟确定性，可直接以文件方式打开，无服务、无构建期依赖、无外部请求、不连真实设备或平台。

**Non-Goals:**

- 不连接真实设备、平台或网络服务，不接收自由文本、不做真实同步或账号操作。
- 不评价具体品牌型号，设备/平台均为去品牌化的功能类别；不收集真实个人信息。
- 不宣称已完整覆盖 HS25 1.3、整本人教版教材或任何真实课堂成效。

## Decisions

1. **一个虚构野外地质考察任务，三个实践环节。** 任务分三阶段：野外（无网、需拍照记录与长续航）、营地（晚间有热点、小组需汇总）、回校（机房稳定联网、要处理数据并出报告）。单一场景让设备约束、平台条件和数据决策相互衔接；泛化的设备清单被否决，因为无法体现任务条件驱动选择。
2. **去品牌化功能候选替代真实型号。** 四个设备候选按离线、拍照、便携、数据处理能力区分（加固平板、轻薄办公本、仅在线的桌面工作站、功能机），三个平台按联网与协作方式区分（离线本地记录 App、实时云端协作文档、仅在线视频网站）。全部为合成数据，避免品牌倾向与真实账号，也让“按条件匹配”可测试。
3. **平台数据环节给出固定协作证据。** 提供一张贡献分布（成员编辑次数/最近同步时间）和一次离线同步冲突记录。学习者要据此判断谁在持续协作、如何处理冲突（先保留双方版本再人工合并，而非直接覆盖），落实“运用平台数据”而非仅选工具。
4. **门槛与本地边界。** 三步都必须选择正确才能进入下一步，错误选择给出与任务条件对应的解释并可重试；全程只在本机模拟，明确网络请求数为 0、不连真实平台。这满足项目本地数据约束，因此交叉表只能推进到 `partial`。
5. **归属高中计算机且只计一次官方分母。** 新页面放在 `computer/high/`，唯一映射到 HS25 信息科技 1.3；不在其他导航另造国家必修分母。卡片、页面清单、搜索目录与发布校验都经仓库现有生成器/检查注册。
6. **复用本地进度契约。** 仅在三步判断都正确后才在 `computer/high` 进度命名空间记录完成；读写失败不得阻断重试或泄露内容，设备与平台选择不写入存储。

## Risks / Trade-offs

- [固定候选可能被当成真实采购建议] → 明确为去品牌化的功能类别示例，真实选择需结合预算、学校规定与具体任务。
- [单一任务的平台匹配可能被外推为通用规则] → 说明匹配基于本例的联网与协作条件，不同任务的合理选择不同。
- [本地演示无法满足“运用平台数据”的完整体验措辞] → HS25 1.3 仅从 `missing` 调整为 `partial`，把真实设备/平台实践与学习者迁移列为剩余工作。
- [离线同步冲突的处理可能被当成平台统一行为] → 说明这是本例固定情境，真实平台的冲突解决机制各有差异。

## Migration Plan

不删除任何既有 URL 或进度结构。新增页面与模型，经现有清单/目录生成注册，更新唯一的 HS25 交叉表条目与证据记录，运行单元/浏览器/静态检查，推送功能提交，核验 Pages 与公开资源后归档本变更。回滚方式为回退该功能提交；不迁移任何外部状态或用户数据。
