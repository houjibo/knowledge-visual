## Context

参见 proposal.md 的差距说明。现有高中查找策略页显示顺序和二分算法的预设轨迹，但不要求学习者生成算法表示。课程映射的 HS25 1.4 已有此页作为部分证据，2025 标准 PDF 镜像 SHA-256 为 `bcbc9c5d7e07b1941c52fd8280ea194fbf4d923700c2ddcd36906ebd9c453d73`。出版方目录将人教版必修 1 第 2 章列为“算法与程序实现”，包含 2.2.2“描述算法”和 2.3.3“语句与程序结构”；教材仍是旧版课标的章次示例。

## Goals / Non-Goals

**Goals:**

- 让学习者亲自选择算法关键步骤，明确循环边界与首次命中后终止。
- 将同一算法以可访问的流程图节点与伪代码并列呈现，再用可观察执行轨迹核验。
- 通过本地纯函数保护输入边界，并只在完整学习步骤和存储成功后记录进度。

**Non-Goals:**

- 不提供通用流程图编辑器、自由代码解释器或对外 AI 服务。
- 不宣称该固定任务覆盖算法全部特征、控制结构、编程实现、复杂度分析或真实学习者掌握。
- 不把人教版旧标准教材目录视为 HS25 要求达成证据；课标映射保持“部分”。

## Decisions

1. **以首次匹配的顺序查找为共同模型。** 使用零起始索引及可重复、可缺席的目标，能用同一个有限任务检验初始化、顺序、相等分支、循环、边界和停止条件。选项中包含常见的 `i <= n` 与从 1 开始等错误，以暴露越界及漏项问题。相比开放拖放任意程序图，它避免自由组合产生无法解释的语义。
2. **从结构化选择生成两种表示。** 学习者在带名称的原生控件中选择六个关键语句；验证后，同一配置驱动 HTML 流程图和伪代码。此方法比拖放更适合键盘和 320px 视口，也避免将视觉位置误当作实际控制流。
3. **模型只解释一条有界轨迹。** 纯模型校验整数数组和目标值，并返回索引、分支、访问数及终止原因；UI 逐步渲染该轨迹。模型不运行 JavaScript 或学习者输入，测试覆盖空列表、首项、末项、重复项、缺席项和错误构造。
4. **完成门槛要求构造、预测、运行和解释。** 仅点选正确结构不算完成，所有预设案例都要在同页完成，循环终止解释也必须正确。存储继续使用站点既有 `SubjectProgress`，以读取和写入结果反馈为准。

## Risks / Trade-offs

- 固定算法可能被误认为学生已经会独立设计程序 → 页面明确称其为“构造练习”，用变体案例检查迁移到不同位置和不存在目标，但课程证据仍标为部分。
- 选择题可能通过猜测完成 → 要求先作输出/访问预测，再运行完整轨迹，并解释循环终止；不把正确选项本身当作掌握证明。
- 流程图在窄屏可能难读 → 使用可换行的语义化节点和文字化分支标识，测试 320px 并核对键盘焦点。
- 非标准算法选项仍可能造成误解 → 每个失败反馈从当前错选语句解释漏项、重复检查或越界，不展示为可运行结果。

## Migration Plan

新增页面与本地模型，更新目录、主题索引、进度总数、课程映射及核查记录；运行模型、桌面/移动、静态和全站发布测试，先推送功能变更再记录 Pages revision 并归档 OpenSpec。回滚时从目录移除卡片及索引引用并恢复映射，旧进度键不需要迁移。
