# parallel-quality-checks Specification

## Purpose
保证完整质量检查在桌面和移动浏览器项目并行执行时仍保留唯一测试清单、真实多重集合等价核对与严格的成功汇总门禁，并保持主分支来源校验、单一发布器及部署后公开版本核验，避免以减少覆盖或放宽失败条件换取速度。

## Requirements

### Requirement: 两项目功能回归复用完整唯一清单

CI MUST 将功能回归以仅含 desktop、mobile 的固定矩阵并行运行，两个项目 MUST 都追加 `--project` 参数调用同一 `npm run test:browser` 入口，不得复制测试文件清单。矩阵 MUST 使用 `fail-fast:false`；必需 job 与测试步骤 MUST 不容忍失败或通过条件跳过。本地完整检查 MUST 继续覆盖全部功能、静态、开发站加载与发布包路径，不新增运行时跳过。

#### Scenario: 两个项目各自运行
- **WHEN** 推送或拉取请求触发完整质量检查
- **THEN** desktop 和 mobile 分别运行原清单中的对应项目，诊断按项目保存，一方失败不取消另一方的正常检查

### Requirement: 拆分清单与完整清单多重集合相等

项目 MUST 从真实的 Playwright JSON 收集结果比较完整入口与两个项目入口；身份 MUST 包含项目、相对文件、行列及完整标题。比较 MUST 保留重复次数，拒绝遗漏、额外项、重复分片、错误项目、空清单或收集错误。配置中新增项目而矩阵未覆盖 MUST 导致等价检查失败。清单检查 MUST 不被表述为测试执行或运行时跳过验证。

#### Scenario: 正常拆分
- **WHEN** 完整清单等于 desktop 与 mobile 清单的多重集合并集
- **THEN** 等价检查通过并报告项目数量与总数

#### Scenario: 少测或重复
- **WHEN** 任一项目少一项、重复一项或出现未覆盖的新项目
- **THEN** 检查失败并定位缺失或额外身份，不能仅凭总数量相同放行

### Requirement: 全部检查成功才允许汇总通过

core job MUST 无条件执行静态、清单等价、开发站全页冒烟和完整 `test:release`。稳定的 `checks` job MUST 直接依赖 core 与功能矩阵，使用 `always()` 进入明确判定，并只接受两项上游结果严格为 `success`。失败、取消、跳过、缺失、空值和未知状态 MUST 都返回失败。汇总 MUST 不需要获取源码或安装依赖，并显式设置不超过五分钟的运行上限。

#### Scenario: 上游全部成功
- **WHEN** core 与两个功能项目都成功
- **THEN** 汇总 checks 成功，后续仍须经过既有主分支和来源校验才可构建发布

#### Scenario: 上游没有成功
- **WHEN** 任一必需上游失败、取消、跳过或缺失结果
- **THEN** 汇总 checks 明确失败，构建和部署不运行

### Requirement: 发布保护与诊断可追溯

配置守卫 MUST 验证矩阵两项目、必需命令与无条件执行、结果绑定、汇总依赖及发布链，拒绝第二个 Pages 发布者。现有 main 头校验、构建来源、最小发布权限、部署后 revision/资源/公网交互 MUST 继续执行。真实 Actions MUST 核实矩阵展开、汇总、构建、部署和核验；平台失败/取消调度若未实测 MUST 明确区别于本地脚本真值表。性能判断 MUST 记录至少三轮时长与覆盖清单，并说明排队是否计入及工作量是否可比。

#### Scenario: 修改绕过某项检查
- **WHEN** 配置删除 mobile、给必需测试加条件跳过或失败容忍、错绑结果或绕过 checks 构建
- **THEN** 静态配置回归拒绝该修改

#### Scenario: 记录实际发布和耗时
- **WHEN** 新流水线在 main 完成一次运行
- **THEN** 记录各 job/步骤状态、源码与公开 revision；性能改善仅在足够可比样本后作结论
