# primary-computer-condition-branches Specification

## Purpose
在小学计算机课程中用固定网格机器人说明单次布尔判断只选择if或else一个动作，将动作前的检查、条件及动作后位置保存在同一可读快照，并保证规则编辑重置、真实完成判定、异常进度保护和静态本地学习的一致性。

## Requirements

### Requirement: 每次判断只执行所选的一个分支
主题 MUST 允许编辑检查右侧或上方有障碍，以及成立/不成立时上右下左四种绝对方向动作。每次手动点击 MUST 从当前位置判断一次，仅执行选中的一个动作；障碍 MUST 包含墙和边界，不执行用户代码或自动循环。

#### Scenario: 两种结果选择不同动作
- **WHEN** 使用默认规则从(1,3)执行两次
- **THEN** 第一次检查右侧畅通，执行不成立分支右移到(2,3)；第二次检查右侧墙面，执行成立分支上移到(2,2)

#### Scenario: 检查和动作方向独立
- **WHEN** 右侧是墙面且成立分支选择向右
- **THEN** 条件为真、仅成立分支被执行、动作因撞墙保持原位并记录碰撞，不执行另一分支补救

### Requirement: 旧位置的判断与动作后位置统一显示
每一步 MUST 显示同一快照的判断前位置、检查坐标与类型、真假、所选分支/动作及动作后位置，并明确标为上次判断。地图 MUST 标出当前机器人及有效的上次检查格；边界外检查 MUST 有可读文字，不把动作后条件覆写为上次判断。

#### Scenario: 最后一次检查仍是假
- **WHEN** 默认路线第六次从(4,1)右移到目标(5,1)
- **THEN** 上次检查为(5,1)畅通、条件为假、执行不成立分支向右，即使新位置右侧为边界也不得把旧结果改为真

### Requirement: 当前规则成功才赢得完成资格
主题 MUST 使用5列3行地图、起点(1,3)、目标(5,1)、墙(3,3)/(5,2)。同一未更改规则下无碰撞、观察真假两种结果并抵达目标时 MUST 赢得完成资格并尝试记录computer/primary/conditional-robot。任意规则更改 MUST 重置当前探索，不得用旧路线的计数证明新规则完成。

#### Scenario: 默认与另一条规则都可完成
- **WHEN** 分别从起点用“查右/真上/假右”或“查上/真右/假上”独立执行六次
- **THEN** 两种规则均无碰撞到达目标、观察真假并尝试保存完成，不依赖规则等于默认值来判定成功

#### Scenario: 修改后重新探索
- **WHEN** 执行若干次后修改任一规则或点击回到起点
- **THEN** 机器人回到起点、判断/碰撞计数清零、最近快照与分支高亮清空，回到起点保留参数，恢复示例恢复默认

### Requirement: 保存状态如实且不损坏历史记录
页面 MUST 仅在SubjectProgress.markComplete实际成功后声称保存；失败或损坏记录 MUST 保留原文、显示未保存并可重试。重置或修改参数 MUST 保留历史完成和此前已赢得但未保存的资格，并在重试时说明保存的是此前完成，不把新探索误报为成功。

#### Scenario: 完成后写入拒绝再重置
- **WHEN** 无碰撞完成后存储拒绝，随后重置并恢复存储点击重试
- **THEN** 当前地图仍为未完成的起点，页面可保存此前赢得的同一主题资格并如实区分当前探索与历史进度

### Requirement: 判断主题可访问且本地静态可用
主题 MUST 提供原生键盘控件、可见焦点、状态播报和地图文字替代，320px无页面横向溢出；在减少动态、file协议和项目子路径中保持操作与进度规则。目录、首页数量与查找 MUST 同步新增主题，保留其他进度与旧URL行为。

#### Scenario: 离线窄屏完成
- **WHEN** 直接打开文件、阻止外部网络并在320px使用键盘操作默认规则六次
- **THEN** 判断、快照、地图及完成反馈正常，页面不依赖服务器或外部请求
