# primary-computer-repeat-loops Specification

## Purpose
通过固定网格、两条方向指令和有限重复次数，让小学学习者对照循环块与展开序列逐步观察轮次、位置和完整程序结果，并在可控运行、可访问操作及诚实保存反馈中理解循环的含义与边界。

## Requirements

### Requirement: 有限循环与展开序列逐条对应

主题 MUST 允许选择两条方向指令作为循环体和 1–4 次重复，默认循环体为向右、向上且重复 2 次。循环块 MUST 与展开序列同时可读；展开指令数 MUST 等于重复次数乘以 2。执行后 MUST 同步显示刚执行的轮次、轮内指令、展开项及累计执行数。说明 MUST 区分循环体方向条目与运行时执行次数，不得宣称循环自动减少实际执行步骤或提高运行速度。

#### Scenario: 重复三次展开为六条
- **WHEN** 学习者选择向右、向上并重复三次
- **THEN** 显示两个方向条目的循环体和六条展开指令，每轮均按向右、向上顺序执行

#### Scenario: 单步状态对应
- **WHEN** 学习者逐条执行一个循环
- **THEN** 每次执行的方向、轮次、轮内位置、展开项及地图位置对应同一条指令，累计数不会超过总数

### Requirement: 运行可暂停且编辑不会混用旧程序

主题 MUST 在打开时保持静止，提供单步、连续运行、暂停、回到起点与恢复示例。暂停 MUST 保持当前执行位置，恢复运行 MUST 从下一条继续；重复点击运行不能创建多个计时器。改变次数或任一循环体方向 MUST 立即停止运行并清空执行状态，以新程序从起点开始。回到起点 MUST 保留当前参数，恢复示例 MUST 恢复默认参数；两者均不得删除历史完成记录。

#### Scenario: 暂停后继续
- **WHEN** 连续执行中学习者暂停并随后恢复
- **THEN** 暂停期间执行数和位置不变，恢复后从下一条指令继续

#### Scenario: 运行时修改程序
- **WHEN** 连续执行中改变重复次数或循环体
- **THEN** 旧计时器停止，位置回到起点，累计数归零，循环块和展开序列显示新的程序

### Requirement: 完整执行与路线反馈决定本机完成

主题 MUST 使用 5 列 5 行固定地图，起点在第 1 列第 5 行、目标在第 4 列第 2 行，并明确标记墙面。向右、向上重复三次 MUST 可无碰撞抵达目标。碰墙或越界 MUST 不移动且显示原因，但计入已执行的指令。只有完整执行后最终在目标且无碰撞 MUST 才判断成功；途中经过目标不得提前停止或记录完成。页面 MUST 在成功后尝试保存 `computer/primary/repeat-loops`，保存失败 MUST 明确提示并提供重试，损坏记录原文不得被覆盖。

#### Scenario: 两次重复尚未抵达
- **WHEN** 默认程序完整执行四条指令
- **THEN** 机器人停在第 3 列第 3 行，显示尚未抵达目标且不新增完成记录

#### Scenario: 三次重复完成目标
- **WHEN** 向右、向上重复三次并完整执行
- **THEN** 机器人停在目标格、显示成功，并尝试保存本机完成标记

#### Scenario: 四次重复途中经过目标
- **WHEN** 向右、向上重复四次且已执行六条
- **THEN** 机器人虽经过目标但仍有两条待执行，尚未记录完成；最终离开目标时显示未完成

#### Scenario: 保存失败恢复
- **WHEN** 成功后写入被拒绝，随后存储恢复并重试
- **THEN** 运行结果保持成功，先明确未保存，恢复后保存同一完成标记而无需重新运行

### Requirement: 主要学习路径可访问并在本地运行

主题 MUST 有清楚的学习目标、返回小学目录入口、有名称的原生控件与可见键盘焦点；状态变化 MUST 可读取。地图 MUST 提供起点、目标、墙面及当前机器人位置的文字替代。320 CSS 像素视口 MUST 无页面级横向溢出。减少动态效果时 MUST 可用单步学习，核心交互 MUST 不依赖外部请求或执行用户代码，并在直接文件、静态服务及项目子路径使用相对资源。

#### Scenario: 键盘与窄屏完成
- **WHEN** 学习者在 320 CSS 像素、减少动态效果设置下使用键盘选择三次并单步执行
- **THEN** 可完成目标、读取轮次和结果，主要内容不溢出

#### Scenario: 文件模式离线操作
- **WHEN** 学习者直接打开主题文件并操作循环
- **THEN** 页面本地资源、展开、执行和反馈可用，操作不发出外部请求
