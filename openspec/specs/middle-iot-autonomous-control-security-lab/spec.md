# middle-iot-autonomous-control-security-lab Specification

## Purpose
通过虚构的校园物联网设备案例，帮助初中学习者在不接触真实设备的前提下，判断供应链可信来源、系统更新维护责任与自主可控做法，理解自主可控技术对物联网安全的意义。

## Requirements

### Requirement: 判断供应链可信来源

学习页面 MUST 让学习者把固定的设备获取与固件更新渠道分为“可信”或“不可信”。官方/可核验签名的渠道与正规更新 MUST 判为可信，不明来源、无法核验或被篡改的固件 MUST 判为不可信。全部判断正确才可完成该环节；误判 MUST 保留重试并说明来源可核验性的依据。

#### Scenario: 拒绝被篡改的固件
- **WHEN** 学习者把“来自不明网盘、无签名校验的网关固件”判为可信
- **THEN** 页面指出无法核验来源、可能被植入恶意代码，属于不可信渠道，并允许重新判断

### Requirement: 认识系统更新与停止维护的风险

页面 MUST 让学习者判断不同维护状态的安全后果：及时安装安全补丁为正确做法，长期忽略更新、使用已停止维护（EOL）的设备存在已知漏洞风险。只有正确识别 EOL 与滞后补丁的风险才可完成该环节；错误判断 MUST 可重试并给出依据。

#### Scenario: 识别停止维护设备
- **WHEN** 学习者认为一台厂商已停止安全更新的物联网设备不再有额外风险
- **THEN** 页面指出 EOL 设备的新漏洞不会被修复、应隔离或更换，并允许重新判断

### Requirement: 用工程属性判断自主可控

页面 MUST 让学习者依据工程属性而非品牌国籍选择增强自主可控的做法，正确选项 MUST 包含数据自持、采用开放标准避免单一锁定、保留可替代方案、关键能力本地化等；把“按品牌国籍一刀切”当作判断依据的选项 MUST NOT 被记为正确。全部选对才可完成该环节。

#### Scenario: 避免以品牌代替可控性判断
- **WHEN** 学习者选择“只要是某国品牌就一定自主可控”作为判断依据
- **THEN** 页面指出自主可控取决于对技术、数据和服务连续性的掌控程度，与品牌国籍没有必然等同关系，并允许重新选择

### Requirement: 本地数据与学习进度边界

页面 MUST 使用固定、合成且不含真实机构信息的输入，不得收集自由文本、发送网络请求或连接外部设备。完成状态 MUST 仅在三个实践环节都正确后记录到本机；本机存储不可用或写入被拒绝时，页面 SHALL 保持学习交互可用并提供重试。

#### Scenario: 存储不可用时继续学习
- **WHEN** 浏览器学习进度存储被拒绝或内容损坏
- **THEN** 页面仍允许完成全部交互任务，明确进度未保存，并在存储恢复后提供重试
