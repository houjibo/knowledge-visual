# 可视化学习站演进计划

状态：执行中的路线图；基线核查日期：2026-11-07。此文件记录目标、顺序和验收，具体行为与任务以各 OpenSpec change 为准。完成一项后重新评估余项，不将路线图当作已实现功能。

## 目标与边界

让不同年龄的学习者能够找到合适的知识点，通过可操作的图示理解概念、练习并获得明确反馈，再方便地继续学习。参考 [AI Agent Handbook](https://aliyun.github.io/ai-agent-handbook/) 的分层目录和阅读引导，具体形式根据学科与学习者需求验证。

保持既有静态部署与直接打开 HTML 的能力；保留现有页面 URL 和学习记录，除非独立变更说明兼容和迁移。计算机与人工智能已拆为两个学科，新旧 URL 和完成记录按独立迁移规则兼容。优先改进已有内容质量，不以页面数量或动画数量作为完成指标。不预设账户、后端或复杂框架。

## 已知起点

- 原始基线（2026-11-07）记录 330 个 HTML 文件；数学小学主题采用目录式页面，其他多为学段目录中的单文件页面。页面形式、共享资源和交互方式并不统一。当前页面数以自动生成的逐页清单为准。
- 首页、学科、学段和模拟世界目录可进入主题，数学小学有知识地图和一条从面积到体积的建议路径；首页支持六个学科、模拟世界分类查找和动手体验入口。计算机与人工智能已有独立入口；模拟世界现含太阳系、齿轮传动、皮带与带轮、曲柄滑块、二维机械臂、工业流水线与仓储分拣场景，目录搜索及数量以逐页清单为准。真实学习者是否容易找到目标仍待验证。
- 现有 Python 检查覆盖部分静态引用及进度数量；Node 测试使用模拟 DOM 检查部分进度逻辑。已为七个模拟场景补充桌面/移动交互回归，也有代表性学科路径、计算机与人工智能核心交互、旧路径迁移和全站桌面加载自动化；大学计算机栈与队列主题已公开验收，全站逐主题交互、教学正确性或无障碍覆盖仍不完整。
- 数学新进度已按学段隔离；同名旧记录无法判定原学段，已保留并提示，参见 [进度说明](../assessments/math-progress-2026-11-07.md)；其他未知与证据见 [差距台账](../gaps.md)。

## 信息架构与目录设计

### 面向学习者

1. **首页 → 学科 → 学段 → 主题** 保留为稳定学科学习主路径；**首页 → 模拟世界 → 场景** 提供不带学科进度语义的模拟入口。
2. 主题目录展示名称、简要学习目标、适用学段和进度；知识地图表达先修或关联时须能解释关系，不能把装饰箭头当作已验证的依赖。
3. 探索主题检索与筛选：先定义名称、别名、学段、空结果和键盘操作场景，再选择试点；搜索结果须直接到达可用主题。避免承诺尚未验证的搜索行为。
4. 主题页面形成可按学科调整的内容骨架：学习目标与前置知识 → 可操控的可视化 → 现象解释 → 练习与反馈 → 总结与下一步；小学、中学、大学可采用不同深度，不强制页面视觉完全一致。
5. 跨学科和专题学习路径只在先修关系和教学内容有依据时添加，清楚标明入口、步骤与完成方式；导航、返回和原 URL 始终可用。

### 面向维护者

- 保持 `math/`、`physics/`、`chemistry/`、`science/`、`computer/` 和 `ai/` 为学科目录；`simulation-world/` 独立组织模拟场景，不继承学段和学科进度；旧 `computer-ai/` 地址保留兼容页。
- 计算机和人工智能后续课程分别以[计算机课程设计](computer-curriculum.md)和[人工智能课程设计](ai-curriculum.md)为地图；每次按 OpenSpec change 小步加入具体主题。
- 评估统一主题元数据：至少覆盖稳定标识、标题、学科、学段、页面路径；别名、目标、先修关系和交互类型按证据扩展。先在一个学科试用并验证离线加载、路径一致性和维护成本，再决定是否推广或生成目录；不要同时维护多份无校验的真相。
- 把可复用但确实一致的交互、样式和进度能力逐步抽到就近的 `assets/`；在行为刻画和引用分析之后合并，避免破坏自包含页面或 `file://`。
- `docs/` 存放长期设计、约束、工作流和路线图；`openspec/specs/` 是已归档行为契约，`openspec/changes/` 是单个增量及历史；`scripts/` 放静态检查，`tests/` 放测试。新增入口在 [AGENTS.md](../../AGENTS.md) 只加索引。

## 交互与学习体验标准

每个新建或实质修改的主题，以可验证的学习目标为先，至少检查：

- **操作与反馈**：用户能够辨认可操作元素；操作后有可感知变化或解释；错误输入、空输入和边界值不会导致无响应或误导；有合理的重置或重新开始方式。
- **概念对应**：视觉变化与数值、单位、公式和说明一致，边界及近似条件有说明；按内容风险记录教材、课程或权威资料等依据与核对人/方式。
- **可访问性与适配**：主要操作可用键盘到达、焦点可见，控件有可理解名称；窄屏不遮挡关键操作和反馈；颜色不是唯一信息载体，动画提供适当的暂停或减少动态效果方式。
- **连续学习**：清楚呈现当前主题和返回入口；按实际规则记录完成，刷新后状态一致。存储不可用或数据损坏时页面仍可使用，并如实处理进度状态。

对历史页面先做盘点和分级，不把以上目标写成全站已达标的事实。对于拖拽、画布、图表和复杂模拟等类型，分别补充等效操作和状态检查。

## 测试策略与完成定义

| 层次 | 范围与方法 | 通过条件 |
| --- | --- | --- |
| 静态完整性 | 所有纳入发布的 HTML：本地链接、资源、必要元数据及导航目标；逐步覆盖 CSS、动态资源和目录数据。 | 基线建立时记录存量问题；新增和修改部分不得引入新错误，存量按变更逐项清零。 |
| 单元和契约 | 进度读写、统计、目录解析、筛选和交互计算等纯逻辑；正常、空值、边界、损坏数据。 | 受改行为有能发现回归的自动化断言，不以行覆盖率代替关键场景。 |
| 浏览器冒烟 | 可发现的所有主题页和导航页在本地静态服务器下逐页打开，检查加载、关键资源和未捕获脚本异常。 | 每次发布运行全量；结果逐 URL 可追踪。已知例外有原因、责任和修复项，不将失败隐藏为通过。 |
| 代表性端到端 | 每个学科、学段及主要交互类型至少一条：导航进入、操作、反馈、返回；进度涉及完成、刷新、恢复、存储不可用。 | 首批先覆盖小学数学、初中物理、高中化学和小学科学各一条，随后覆盖其余学段和识别出的交互类型；每个新交互类型随首次交付补一条。 |
| 受影响主题功能 | 建立按主题的操作清单；逐步覆盖每一页的核心学习操作、正确/错误反馈和重置；内容或共享组件变更按影响范围回归。 | 每个声明为已验收的主题都有可执行测试或附证据的人工记录；未经检查的页面明确标为未验证。 |
| 视觉与无障碍 | 桌面和窄屏截图/人工检查，键盘操作、焦点、名称及对比度；自动扫描辅助发现问题。 | 受改路径的关键内容不被遮挡，主操作可键盘完成；自动扫描与人工检查各自记录覆盖和例外。 |
| 科学与教学 | 依据学习目标核对公式、单位、示例与交互结果，涉及风险的内容交叉核验来源。 | 每个新建或实质修改的主题记录依据和验证者/方式；未核验内容不得标为已验收。 |

浏览器方案先做小型试验，评估可维护性、安装体积、离线需求和 CI 可运行性；不把模拟 DOM 当成真实浏览器。验证静态服务器部署和直接打开 `file://` 两种使用方式：至少对关键导航与代表性主题分别运行，若工具不能覆盖文件协议则保留可复现的手工验证记录。外链、动态脚本、浏览器版本和跨设备差异需明确记录边界。

## 分阶段交付

每阶段是目标而不是一个大提交；每个切片建立独立 change，明确验收、依赖、回滚与检查，完成即提交并推送。

### 0. 建立可观察基线（优先）

- 已生成 [逐 HTML 静态清单](../assessments/README.md)，记录路径、学段和交互线索；尚需盘点每页核心交互、真实验证状态，并调查动态入口与无效链接。
- 已对 4 个代表主题做 [桌面浏览器抽查](../assessments/browser-pilot-2026-11-07.md) 并修复三个顶层模式入口；仍须补错误、刷新、窄屏、控制台和内容依据。
- **验收**：有可复现的基线报告、逐页清单和优先级排序；缺失证据标记未验证。后续阶段以该报告与变更差异驱动。

### 1. 让现有学习可靠

- 已建立 330 页桌面浏览器加载冒烟并修复首轮发现的四个初始化故障；继续修复阻断学习、完成或导航的问题，扩展四条代表路径。
- 单独设计数学进度隔离和旧数据兼容：列举跨学段同名项、旧记录的歧义和不可逆影响；保留原始数据，验证新旧记录、异常存储、回退与恢复，再决定迁移策略。
- **验收**：所选路径可从首页到主题、完成一次交互并返回；受影响浏览器测试、原有检查和数据兼容测试通过，遗留项有证据和负责人/后续 change。

### 2. 目录与发现体验

- 对照真实查找任务评估首页、学科、学段及知识地图；先在一个学科试点主题元数据、目录一致性、清晰标题及必要的查找能力。
- 检验直达 URL、原链接、直接打开、空结果、键盘和窄屏；确认维护成本后再按学科推广。
- **验收**：试点可以通过学段目录与所选发现方式找到同一主题；新增或删除主题时检查能发现导航、元数据、进度统计之间的漂移。

### 3. 交互体验与教学质量

- 建立交互类型与质量清单，按学习价值和问题严重程度选择代表主题，逐个改进可操控性、反馈、解释和重置；同步核验概念。
- 只抽取经实际页面证明一致的公共能力；为共享代码和代表调用页补回归。
- **验收**：每个完成的主题满足本文件交互标准并留下内容依据、浏览器与键盘验证；未迁移主题保留其原行为和链接。

### 4. 系统化覆盖与持续维护

- 将全站浏览器冒烟、逐主题核心操作清单、变化影响选择及知识复核纳入例行检查；按风险逐步扩大跨浏览器、无障碍和移动设备覆盖。
- 一键检查及 CI 已在远端 Linux 多次通过，包含全站加载、发布构建、Pages 部署与部署后核验；持续明确本地、CI 与人工项，失败输出定位与复现步骤，再按实际效果改进门禁。
- **验收**：所有发布页面纳入冒烟清单；每个主题的功能与内容验证状态可追踪；新变更不得降低既有通过的覆盖，缺陷有复现、回归验证和关闭证据。

### 5. 独立站点与专业化运营（与质量建设并行）

- 以现有静态站为基础建立可公开访问的 HTTPS 站点；先验证 GitHub Pages 项目站的路径与发布流程，再按需要接入用户拥有的独立域名。公开站、域名和托管可分别迭代，不将仓库推送视为发布完成。
- 建立发布包白名单、CI 检查、已发布版本可追溯、发布后冒烟与故障回退；选择适合儿童与学习者的反馈渠道，明确隐私与第三方资源边界。
- 制定内容质量与维护职责：概念依据、学习路径、可访问性、报告问题、复核与持续改进。首批只对有证据的路径作完成声明，其余保持可追踪的待核验状态。
- **验收**：用户可通过稳定网址从首页完成代表性的学习操作；桌面及窄屏、HTTPS、资源与深层链接、基本元信息和已发布版本均经验证；发布失败可定位并有回退步骤。

具体步骤、候选部署方案、待确认事项和验收见 [站点发布与专业化运营计划](site-operations.md)。

## 执行与更新

1. 每次从 [差距台账](../gaps.md) 和本计划选一个可在短周期内验证的切片；`openspec new change <name>` 后记录目标、场景、设计取舍、任务和证据。
2. 改动前保留现有工作；先建立可观察反馈，完成后运行与风险相称的检查、更新契约和文档、归档 change。
3. 每个通过验收的切片尽快提交并推送，推送失败时保留提交并报告具体原因；不能将本地提交称为已发布。
4. 每完成切片更新本计划中的阶段状态和差距；当用户需求或证据改变时重新排序。定期清理过期假设，保持 AGENTS.md 为索引。
