# 站点发布与专业化运营计划

状态：目标与实施计划，非已发布承诺。基线核查：2026-11-07。项目首先是供不同年龄学习者动手探索的可视化学习站；工程化和 AI 辅助维护服务于内容准确、学习流畅和长期可用。

## 目标

- 提供不依赖代码仓库或本地服务的公开 HTTPS 站点，有稳定可分享的首页和主题链接；在成熟后支持用户拥有的独立域名。
- 使用清楚、可重复的发布与回退流程，让每次公开更新对应经过验证的版本，并能快速发现和修复故障。
- 建立内容、体验和维护质量标准：明确学习目标、概念依据、交互反馈、可访问性、问题反馈和修复记录。
- 用 AI 辅助分析与实施，以仓库文档、OpenSpec、自动测试和可复核结果保持知识与决策可追溯。

## 当前基线

仓库 `houjibo/knowledge-visual` 为公开仓库、默认分支为 `main`；2026-11-07 公共 GitHub API 返回 `has_pages: false`。已有静态 HTML 站点、根目录预览方式、GitHub Actions 检查及分主题浏览器测试；新增按受控目录和类型生成的发布包，并在子路径运行四学科代表性交互，远端检查结果和公网发布尚未核实。部分学习进度存于浏览器本地，跨设备或更换域名不会自动同步。独立域名、域名所有权、托管及反馈渠道尚未确定。

## 分阶段执行

### 1. 构建可发布的静态产物

1. 已通过 `python3 scripts/build_site.py --output <新目录>` 从 Git 跟踪的允许目录和静态文件类型生成发布包，排除文档、测试及备份；保留原有路径。新增资源类型需更新允许清单及检查。
2. 发布包构建检查 HTML 声明的站内链接和根路径引用，并拒绝覆盖现存目录；CSS、动态路径、外链及大小写跨平台差异仍需继续检查。
3. `npm run test:release` 在独立临时目录的子路径检查首页搜索及四学科代表交互，覆盖桌面和窄屏；该项不证明全站交互、知识内容或所有进度场景均已验证。

### 2. 建立公开站点和发布流程

1. 首选试点 GitHub Pages：仓库已公开，静态站可由 GitHub Actions 发布；项目站默认地址预计为 `https://houjibo.github.io/knowledge-visual/`，**仅启用并实际部署后才是有效地址**。该选项不排除后续迁移其他静态托管服务。
2. 新增受控的发布流水线：默认分支的目标提交通过静态与浏览器检查后，将同一提交构建出的产物交给部署；记录提交、构建和部署结果。避免拉取请求直接发布，以及并发旧构建覆盖新版本。
3. 确认 Pages 配置、工作流权限和发布来源；部署后从公网检查 HTTPS、首页、深层 URL、资源、搜索、代表交互、移动视口与浏览器错误，并记录实际地址、版本和时间。故障时停止宣称发布成功。
4. 制定并演练回退：保留已知可用的版本和构建记录，用明确的重发流程恢复；确认静态资源和浏览器缓存行为。发布失败不覆盖原来可用版本。

### 3. 独立域名与产品入口

- 先选择并确认域名的所有权、续费责任和 DNS 管理方式；接入前核查成本和服务可用性。配置域名验证、DNS 和 HTTPS，确认旧项目站链接及外部深链的处理方式。
- 当前进度是按浏览器来源保存；域名变更会产生不同的存储来源，迁移前须设计可回退的导出、导入或提示，不声称可自动继承学习记录。
- 补充适当的网站名称、简介、图标、分享元信息及站点地图；以真实学习路径为依据设计首页的起点、搜索、学科与学段入口。

### 4. 质量、维护与反馈

- **内容治理**：每个实质修改的主题记录适用范围、权威依据和可复现验证；高风险或未核验内容明确标注状态，给出反馈与修正路径。
- **工程与发布**：公开 CI 结果、变更记录与版本；建立自动化静态检查、真实浏览器回归和发布后巡检。依实际使用与维护能力确定可用性目标，而不是预设无法验证的 SLA。
- **可访问与适配**：持续覆盖键盘、清晰名称、焦点、减少动态效果、窄屏与必要的屏幕阅读反馈；以受影响路径的实测证据为准。
- **隐私与安全**：默认避免收集个人数据；启用统计、反馈表单或第三方脚本前明确用途、数据流与隐私说明。学习者可能为未成年人，反馈设计应避免要求不必要的身份信息。
- **运营与责任**：在 README 或站点提供可用的问题反馈入口、维护方式和内容更正流程；明确维护者、升级路径和依赖更新安排。成本、备份和域名续费有实际负责人后再作承诺。

## 验收与待决事项

首个公开站上线需有：公网 HTTPS 地址及提交版本；首页到至少四学科代表主题的可复现学习路径；桌面、窄屏、深层链接和搜索检查；发布成功和失败记录；回退方法；测试和内容覆盖边界。域名阶段另需验证所有权、HTTPS、旧链接及本地学习进度处理。

待确定：是否使用自有域名及其名称、域名/DNS 管理权、托管偏好、反馈渠道、服务可用性目标。无需等待这些事项即可先完成发布包和子路径验证；涉及实际域名或托管账户的操作以可用权限和明确选择为准。
