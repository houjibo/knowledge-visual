# 持续重构

本流程从 `eng-explore`、`eng-design`、`eng-plan`、`eng-change`、`eng-verify` 提炼，原始来源见 [来源说明](README.md)。

1. 查清现状、受影响页面与依赖；指出具体维护痛点，区分结构调整与行为变化。
2. 选择一个可回退的小切片，记录保持不变的行为、验证方式和风险；较大工作在 OpenSpec change 中分解，纯重构按 CLI 支持的方式声明无需规格变更。
3. 先建立适当的现有行为反馈，修改一个切片后立即验证；失败先定位，不叠加其他重构。
4. 检查共享资源的调用方、静态引用和必要的浏览器交互；记录未覆盖范围，更新架构与差距。需要改变产品行为时转入需求交付。
