# 问题解决

本流程从 `eng-explore`、`eng-clarify`、`eng-diagnose`、`eng-change`、`eng-verify` 提炼，原始来源见 [来源说明](README.md)。

1. 记录版本、环境、触发条件、预期和实际结果及影响；尽量复现，无法复现时保留观测和限制。
2. 区分症状与原因，提出可证伪假设及各自预测；做低风险、能区分假设的实验，记录支持或排除的证据。
3. 确定证据足够的修复方向；区分临时止血和根因修复。行为变化或较大修复用 OpenSpec 记录范围、验收与任务。
4. 小步修复，验证原问题、相关路径和适当的反例；记录结果、未排除原因及回归覆盖。无法验证时如实标记，不宣称问题彻底解决。
