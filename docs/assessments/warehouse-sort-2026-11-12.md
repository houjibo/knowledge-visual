# 仓储分拣模拟核查

状态：开发与验证中。范围由[当前 OpenSpec 变更](../../openspec/changes/2026-11-12-warehouse-sorting-simulation/proposal.md)界定。

## 差距与学习问题

既有工业流水线展示三个串行工位的加工与瓶颈，缺少分流后两个独立队列的对照。新增页面用固定A/A/B标签的12件包裹，让学习者预测首个排队口，并观察一口积压时另一口可能空闲。术语依据为[MIT OCW 排队讲义](https://ocw.mit.edu/courses/1-225j-transportation-flow-systems-fall-2002/55cc67c8b32d96052f72a4a7ead51393_lec8queues.pdf)；并行独立队列的教学背景见[NPTEL](https://archive.nptel.ac.in/content/storage2/courses/105101008/585_Queuing/point6/point.html)。本站模型为固定有限批次，没有使用随机稳态方程。

## 模型与边界

- A/B分拣口各一次只处理一件，队列先到先处理；整数到达间隔1–3秒，每口处理时长1–4秒。时间0首件到达，每步先完成、再到达、最后开工。无运输、故障、错分、有限缓冲或随机波动。
- 默认A口3秒、B口1秒：A首先排队，A/B最大等待4/0件，12件在第24模拟秒全部完成。A口1秒、B口4秒：B首先排队，最大等待0/1件，第18秒完成。两口1秒：全程无等待，第12秒完成。
- 页面只比较有限批次的完成时间与队列峰值，不将其写成真实仓储长期吞吐能力、设备承诺或学科进度。

- 纯模型在48组合法参数下逐件对照独立事件排程，核对每件完成时刻、两口等待峰值、首个排队口、12件守恒与结束；参数和损坏状态边界通过。
- 桌面和移动专项14项通过：分类搜索、三种预测、两轮完成对照、重置、计时器停止、减少动态偏好、file直开、320px键盘单步及发布子路径。首次桌面原生选择框的模拟方向键行为不稳定，测试改为原生选择值并保留键盘激活按钮；页面仍采用可访问的原生选择框。
- `CI=true npm run check` 完整通过：严格OpenSpec及静态检查通过；功能浏览器2068项通过、6项按配置跳过；开发站372页、发布路径16项、发布包372页通过。仓储分拣在本地浏览器实测第1秒出现P2等待，A口预测正确，B口仍空闲。
