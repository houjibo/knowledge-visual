# 全站浏览器加载检查（2026-11-07）

使用 Playwright 1.65.0、本机 Google Chrome 156.0.8078.81、桌面 1280×720 和回环 HTTP 静态服务器，对清单中的 330 个 HTML 文件分别建立新浏览器上下文并加载。检查页面 HTTP 200、非空标题、加载过程中同源 HTTP 错误和未捕获 JavaScript 异常；页面触发 load 后再观察 200 毫秒。

首次运行 326 通过、4 失败：负数页面调用不存在的导航函数；几个和第几页面访问作用域外变量；认识平均分和认识质量单位在某些随机题目下无限循环。修复后重新运行，**330/330 加载检查通过**。另有针对四个受影响页面的边界题目和初始化浏览器回归；详情见对应 OpenSpec 变更记录。

在已安装开发依赖和 Chromium 后，运行 `npm run test:browser:smoke`；如使用本机兼容浏览器，可设置 `KV_CHROMIUM_PATH`。命令先检查清单是否与实际文件一致，再逐页面报告失败。浏览器版本、随机题目和资源状态会影响结果，历史通过不保证以后通过。

此检查不是全站功能验收：只覆盖桌面 Chromium、HTTP 和有限的加载时间窗口；不覆盖操作后或更晚的错误、外链与其他来源资源、真实窄屏布局、`file://`、读屏器、知识准确性及所有随机输入。交互和边界场景需按主题继续验证。

后续以 CI 双工作进程复跑时，`math/topics/numbers/index.html` 因找数字目标为 1 或 50 而偶发超时：±10 范围不足以填满 12 个不同数字。已改用有限候选集合，并添加固定随机边界的浏览器回归；这次发现说明一次全站通过不能证明随机生成在所有取值下都能结束。

同次双工作进程检查还发现“搭配中的学问”和“位置与顺序”在部分题型下可选干扰项不足而超时，已改为有限候选集；针对两数字排列和四人间隔题添加确定性浏览器回归，验证四个不同选项及正确反馈。

后续进度回归发现小学分数页在分母为 2 时会无限等待不同分子，且比较按钮事件未绑定；修复后以固定随机值验证 1/2 = 1/2 正确计分，完整加载冒烟再次通过。
